# 30-移动测试基础

> 课时：45 min | 难度：★★☆☆☆

## 学习目标

- 理解移动端测试与 Web 端测试的核心差异
- 掌握移动测试的五大类型及其应用场景
- 了解 Android 与 iOS 平台的关键差异
- 理解移动设备碎片化带来的测试挑战
- 掌握移动测试金字塔模型
- 区分模拟器、真机、云测试的适用场景
- 能够针对移动端特性设计测试用例

## 核心概念

### 30.1 移动端测试的五大类型

| 测试类型 | 核心关注点 | 典型工具 |
|---------|-----------|---------|
| 功能测试 | 应用逻辑正确性、业务流程完整性 | Appium, Espresso, XCUITest |
| 性能测试 | 启动速度、内存占用、CPU 使用率、帧率 | Perfetto, Instruments, Systrace |
| 兼容性测试 | 不同系统版本、屏幕尺寸、厂商 ROM | BrowserStack, Sauce Labs |
| 可用性测试 | 交互流畅度、手势响应、视觉一致性 | 人工走查 + A/B Testing |
| 安全测试 | 数据传输加密、权限滥用、存储安全 | Drozer, MobSF, Frida |

### 30.2 Android 与 iOS 平台差异

**设备碎片化**
- Android：数千种设备型号，厂商定制 ROM（MIUI、HarmonyOS、OneUI 等），屏幕尺寸与分辨率种类繁多
- iPhone：Apple 统一硬件生态，型号有限，系统更新率高

**权限模型**
- Android：运行时权限（Android 6.0+），部分权限需特殊申请（如悬浮窗、通知监听）
- iOS：隐私标签强制要求，ATT 框架限制跨应用追踪，权限粒度更细

**生命周期**
- Activity / Fragment 生命周期管理影响页面状态恢复
- iOS ViewController 生命周期与 Android 不同，内存回收策略更激进

**后台机制**
- Android 允许后台 Service、BroadcastReceiver，不同厂商后台限制策略差异大
- iOS 后台模式受限，统一通过 Background Tasks 框架管理

### 30.3 移动测试挑战

**设备碎片化**
测试矩阵随设备型号、系统版本、屏幕尺寸、厂商定制呈指数增长。测试策略需基于用户分布数据裁剪优先级。

**网络条件**
移动网络存在 2G/3G/4G/5G 切换、弱网、断网、飞行模式等场景。Charles Proxy 和 Network Link Conditioner 可模拟。

**电量与资源**
高 CPU 占用导致发热降频，内存不足触发系统杀进程（Android Low Memory Killer / iOS jetsam）。需关注应用在低电量模式下的表现。

**中断事件**
来电、短信、通知推送、闹钟、低电量警告等系统事件打断应用运行。应用需正确处理中断并恢复状态。

### 30.4 移动测试金字塔

```
        /  UI 测试  \        ← 少量，覆盖核心业务流程（Appium）
       /------------\
      /  集成测试    \      ← 服务间交互、API 契约（Postman, Retrofit Mock）
     /--------------\
    /   单元测试      \     ← 大量，覆盖核心逻辑（JUnit, XCTest）
   /------------------\
```

移动测试金字塔遵循"越底层测试越多、越快"的原则。UI 测试因设备依赖和脆弱性（元素定位变动）成本高，应聚焦黄金路径。

### 30.5 测试环境对比

| 维度 | 模拟器/模拟器 | 真机 | 云测试平台 |
|-----|-------------|------|-----------|
| 成本 | 免费 | 高（购买+维护） | 按需付费 |
| 覆盖度 | 系统版本、分辨率 | 真实硬件特性 | 海量真机池 |
| 传感器 | 有限（GPS 模拟） | 完整（陀螺仪、NFC） | 完整 |
| 性能 | 不反映真实性能 | 真实 | 真实 |
| CI 集成 | 容易 | 困难 | 中等 |
| 适用阶段 | 开发调试、单元测试 | 回归验证、性能基线 | 兼容性测试 |

### 30.6 移动端测试用例设计要点

**手势操作**
- 单指：tap、long press、swipe、drag
- 双指：pinch（缩放）、rotate
- 边缘手势：返回手势（Android 侧滑、iOS 从左边缘右滑）
- 3D Touch / Haptic Touch（iOS）

**传感器依赖**
- 加速度计：摇一摇、计步
- 陀螺仪：全景浏览、游戏控制
- GPS：定位、地理围栏
- 光线传感器：自动亮度影响 UI 可见性
- 距离传感器：通话熄屏

**通知系统**
- 通知栏展示、点击跳转、通知分组
- 通知权限未授予时的降级处理
- 锁屏通知交互
- 通知点击后应用状态恢复

## 动手实操

### 30.7 检查设备测试矩阵

根据应用目标用户的设备分布数据（可通过 Firebase Analytics、友盟等统计），筛选优先级最高的组合：

```
系统版本：Android 10+ 覆盖率 ≥ 90% 则最低支持 Android 10
屏幕比例：16:9、18:9、19.5:9、20:9 各至少一台
厂商：覆盖 Top 5 厂商（小米、华为、OPPO、vivo、三星）
分辨率：720p、1080p、2K 各一台
```

### 30.8 设计中断测试用例

来电中断测试流程：
1. 启动应用并进入目标页面
2. 执行模拟来电（ADB: `adb shell am start -a android.intent.action.CALL`）
3. 验证应用进入 pause 状态（非 crash）
4. 模拟挂断
5. 验证应用正确恢复，数据不丢失，页面状态一致

通知中断测试流程：
1. 打开测试应用，执行登录操作
2. 将应用切至后台
3. 发送推送通知（可通过 Firebase Console 或 ADB）
4. 点击通知
5. 验证跳转到正确页面，携带正确参数

## 常见坑

- 忽视 Android Doze 模式对后台任务的限制，导致推送延迟测试遗漏
- 仅测试竖屏，忽略横屏模式下的布局异常（Android `configChanges`，iOS `supportedInterfaceOrientations`）
- 权限拒绝场景覆盖不全，特别是"不再询问"选项被勾选后的降级逻辑
- 键盘弹出导致元素被遮挡，未处理 `adjustResize` / `adjustPan` 差异
- 浅色/深色模式切换未测试，Android 10+ 和 iOS 13+ 均支持系统级深色模式
- 忽略不同厂商对后台进程管理的激进程度差异（如华为 EMUI 杀后台严重）
