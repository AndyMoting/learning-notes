# 50-测试左右移

> 课时：40 min | 难度：★★★★☆

## 学习目标

- 理解 Shift-Left 和 Shift-Right 的核心理念
- 掌握测试金字塔各层级的比例关系
- 能够实施具体的左移和右移实践
- 理解缺陷逃逸率、平均检测时间等度量指标

## 核心概念

### Shift-Left 测试

Shift-Left 的核心思想：将测试活动尽可能提前到软件开发生命周期的早期阶段。

```
传统模式：      [需求] → [设计] → [编码] → [测试] → [部署]
左移模式：      [测试] → [测试] → [测试] → [验证] → [验证]
                      ↑    ↑    ↑
                   评审  静态分析 TDD
```

左移的具体实践：

| 实践 | 阶段 | 描述 |
|------|------|------|
| 需求评审 | 需求阶段 | 识别模糊/不可测试的需求 |
| 静态代码分析 | 编码阶段 | SonarQube、ESLint 自动扫描 |
| TDD | 编码前 | 先写测试再写实现 |
| BDD | 需求分析 | 用通用语言描述行为 |
| 代码评审 | 提交前 | 同行审查测试覆盖率和测试质量 |

### Shift-Right 测试

Shift-Right 在发布后环境中进行测试，验证真实用户场景下的系统表现。

| 实践 | 工具示例 | 目的 |
|------|----------|------|
| 监控/告警 | Prometheus + Grafana | 实时发现生产异常 |
| 金丝雀发布 | Argo Rollouts | 小流量验证新功能 |
| 功能开关 | LaunchDarkly | 控制功能灰度放量 |
| 混沌工程 | Chaos Monkey | 验证系统弹性 |
| A/B Testing | Optimizely | 验证不同方案的效果差异 |

### 测试金字塔

测试金字塔定义了不同层级测试的数量比例和执行速度期望：

```
        /\
       /  \        ← E2E 测试（少量，慢，昂贵）
      / 5% \          执行时间：分钟级
     /--------\
    /   15%    \    ← 集成测试（中等量）
   /------------\      执行时间：秒级
  /    80%       \  ← 单元测试（大量，快，便宜）
 /----------------\    执行时间：毫秒级
```

三层测试的职责边界：

- **单元测试**：验证单个函数/方法的正确性，隔离依赖
- **集成测试**：验证模块间接口、数据库交互、消息队列等
- **E2E 测试**：验证完整的用户流程，模拟真实用户操作

反模式——冰淇淋筒（Ice Cream Cone）：

```
    ___________
   /           \      ← 大量手动 E2E（慢、脆、贵）
  /  手动测试    \
 /----------------\
/    少量自动化    \
\------------------/
```

### 度量指标

**缺陷逃逸率（Defect Escape Rate）**：

```
缺陷逃逸率 = 生产环境发现的缺陷数 / 总发现缺陷数 × 100%

目标值：< 5%（成熟团队通常控制在 2%~3%）
```

**平均检测时间（Mean Time to Detect, MTTD）**：

```
MTTD = Σ(缺陷发现时间 - 缺陷引入时间) / 缺陷总数

左移效果：MTTD 缩短意味着缺陷在更早期被发现
```

**平均修复时间（Mean Time to Repair, MTTR）**：

```
MTTR = Σ(缺陷修复完成时间 - 缺陷报告时间) / 缺陷总数
```

## 动手实操

### 实操1：实施 TDD（测试驱动开发）

以"字符串计算器"为例演示 TDD 三步循环：

```python
# test_calculator.py
import pytest
from calculator import StringCalculator


class TestStringCalculator:
    """字符串计算器 - TDD 实现"""

    def test_empty_string_returns_zero(self):
        """第一步：空字符串返回 0（红色 → 实现 → 绿色）"""
        assert StringCalculator.add("") == 0

    def test_single_number(self):
        """第二步：单个数字返回该数字"""
        assert StringCalculator.add("1") == 1

    def test_two_numbers_comma_separated(self):
        """第三步：两个逗号分隔数字返回和"""
        assert StringCalculator.add("1,2") == 3

    def test_multiple_numbers(self):
        """第四步：多个数字返回和"""
        assert StringCalculator.add("1,2,3,4,5") == 15

    def test_newline_delimiter(self):
        """第五步：支持换行符作为分隔符"""
        assert StringCalculator.add("1\n2,3") == 6

    def test_negative_numbers_raise_exception(self):
        """第六步：负数抛出异常"""
        with pytest.raises(ValueError, match="负数不允许: -1"):
            StringCalculator.add("1,-1")

    def test_numbers_over_1000_ignored(self):
        """第七步：大于1000的数字被忽略"""
        assert StringCalculator.add("2,1001") == 2
```

```python
# calculator.py
import re


class StringCalculator:
    """字符串计算器 - TDD 实现产物"""

    @staticmethod
    def add(numbers: str) -> int:
        if not numbers:
            return 0

        # 解析数字（支持逗号和换行符分隔）
        num_list = re.split(r'[,\n]', numbers)
        
        negatives = []
        total = 0
        
        for num_str in num_list:
            num = int(num_str)
            if num < 0:
                negatives.append(num)
            elif num <= 1000:
                total += num
        
        if negatives:
            raise ValueError(f"负数不允许: {', '.join(map(str, negatives))}")
        
        return total
```

### 实操2：集成测试（Shift-Left 中层）

```python
# test_order_integration.py
import pytest
from httpx import AsyncClient
from sqlalchemy.ext.asyncio import AsyncSession


class TestOrderIntegration:
    """订单模块集成测试 - 验证服务层与数据库交互"""

    @pytest.fixture
    async def db_session(self, test_db):
        """提供真实的测试数据库会话"""
        async with test_db() as session:
            yield session

    @pytest.fixture
    async def test_user(self, db_session: AsyncSession):
        """构造测试用户数据"""
        user = UserFactory.create()
        db_session.add(user)
        await db_session.commit()
        return user

    @pytest.mark.asyncio
    async def test_create_order_persists_to_db(
        self, 
        db_session: AsyncSession, 
        test_user
    ):
        """验证订单创建后正确持久化到数据库"""
        # Arrange
        order_service = OrderService(db_session)
        order_data = {
            "user_id": test_user.id,
            "items": [{"product_id": 100, "quantity": 2}],
            "total_amount": 199.98
        }

        # Act
        order = await order_service.create_order(**order_data)

        # Assert - 从数据库重新读取验证持久化
        result = await db_session.get(Order, order.id)
        assert result is not None
        assert result.user_id == test_user.id
        assert result.total_amount == 199.98
        assert result.status == "pending"
```

### 实操3：Shift-Right 监控验证

```python
# monitoring/checks.py
"""生产环境健康检查 - Shift-Right 实践"""

from prometheus_client import Histogram, Counter, Gauge

# 定义业务指标
order_creation_duration = Histogram(
    'order_creation_duration_seconds',
    '订单创建耗时',
    buckets=[0.1, 0.25, 0.5, 1.0, 2.5, 5.0]
)

payment_failure_counter = Counter(
    'payment_failures_total',
    '支付失败次数',
    ['payment_method', 'error_type']
)

active_users_gauge = Gauge(
    'active_users_count',
    '当前活跃用户数'
)


class TestProductionMonitoring:
    """生产监控验证"""

    def test_order_creation_latency_sla(self):
        """验证订单创建延迟满足 SLA（P99 < 500ms）"""
        p99_latency = order_creation_duration.observe(0.5)
        assert p99_latency < 0.5, f"P99 延迟 {p99_latency}s 超过 SLA"

    def test_payment_failure_rate_alert(self):
        """验证支付失败率超过阈值时触发告警"""
        failure_rate = payment_failure_counter._value.get()
        assert failure_rate < 0.01, "支付失败率超过 1%"
```

## 常见坑

1. **测试金字塔倒置**：大量 E2E 测试、极少单元测试——反馈慢、维护成本高
2. **左移停留在口号**：仅实施代码评审，忽视需求质量的左移
3. **右移忽视可观测性**：没有日志、指标、链路追踪就无法实施真正的右移
4. **混淆测试层级**：端到端测试中做了大量单元级别的断言，导致定位困难
5. **覆盖率盲目追高**：100% 行覆盖率不代表有效测试，可能测试了实现而非行为
