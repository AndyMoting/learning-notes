# 46-CD 实战
> 课时：90 min | 难度：★★★★

## 学习目标
- 设计完整的 CI/CD 流水线，从代码提交到部署通知
- 掌握多阶段工作流编排（lint → unit → integration → e2e）
- 理解制品（Artifact）管理与部署门禁机制
- 能集成钉钉/Slack/邮件等多种通知渠道

## 核心概念

### CD 流水线完整架构

```
代码提交
    │
    ▼
┌─────────────────────────────────────────────────────┐
│                  CI Pipeline                         │
│                                                      │
│  ┌──────┐   ┌──────────┐   ┌────────────┐          │
│  │ Lint │ → │ Unit Test│ → │ Integration │          │
│  │ 代码  │   │ 单元测试  │   │  集成测试    │          │
│  │ 检查  │   │          │   │            │          │
│  └──────┘   └──────────┘   └────────────┘          │
│       │                         │                    │
│       │    ┌────────────┐       │                    │
│       └ →  │  E2E Test  │ ← ───┘                    │
│            │ 端到端测试   │                           │
│            └────────────┘                            │
│                 │                                    │
│                 ▼                                    │
│          测试报告聚合                                 │
└─────────────────────────────────────────────────────┘
    │
    │ 所有测试通过
    ▼
┌─────────────────────────────────────────────────────┐
│                  CD Pipeline                         │
│                                                      │
│  ┌──────────┐   ┌──────────┐   ┌──────────┐        │
│  │ Artifact │ → │  Deploy  │ → │  Smoke   │        │
│  │  制品发布  │   │  环境部署  │   │ 冒烟测试  │        │
│  └──────────┘   └──────────┘   └──────────┘        │
│                                      │              │
│                                      ▼              │
│                                 通知团队              │
└─────────────────────────────────────────────────────┘
```

### 流水线设计原则

1. **Fail Fast**：将最快速、最廉价的检查放在最前面（lint 先于测试）
2. **阶段隔离**：上一阶段失败则后续阶段不执行，避免资源浪费
3. **制品传递**：构建产物通过 Artifact 在阶段间传递，不重复构建
4. **门禁控制**：关键阶段（部署前）设置人工审批或自动化检查
5. **可追溯**：每次流水线执行都有完整日志与报告归档

## 动手实操

### 实操 1：完整多阶段工作流

```yaml
# .github/workflows/full-pipeline.yml

name: Full CI/CD Pipeline

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

# 环境变量
env:
  PYTHON_VERSION: '3.11'
  REGISTRY: ghcr.io
  IMAGE_NAME: ${{ github.repository }}

jobs:
  # ========== Stage 1: 代码质量检查 ==========
  lint:
    name: 代码质量检查
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: ${{ env.PYTHON_VERSION }}

      - name: 安装检查工具
        run: pip install flake8 black isort bandit mypy

      - name: Flake8 规范检查
        run: flake8 src/ tests/ --max-line-length=100 --statistics

      - name: Black 格式检查
        run: black --check src/ tests/

      - name: isort 导入排序检查
        run: isort --check-only src/ tests/

      - name: Bandit 安全扫描
        run: bandit -r src/ -l -f json -o reports/bandit.json
        continue-on-error: true

      - name: 上传安全扫描报告
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: security-report
          path: reports/bandit.json

  # ========== Stage 2: 单元测试 ==========
  unit-test:
    name: 单元测试
    needs: lint
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: ${{ env.PYTHON_VERSION }}

      - name: 缓存依赖
        uses: actions/cache@v4
        with:
          path: ~/.cache/pip
          key: pip-${{ hashFiles('requirements.txt') }}
          restore-keys: pip-

      - name: 安装依赖
        run: |
          pip install -r requirements.txt
          pip install -r requirements-test.txt

      - name: 运行单元测试
        run: |
          pytest tests/unit/ \
            -v \
            --cov=src \
            --cov-report=xml:reports/coverage.xml \
            --cov-report=html:reports/htmlcov \
            --junitxml=reports/junit-unit.xml

      - name: 上传测试报告
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: unit-test-reports
          path: reports/

      - name: 检查覆盖率门禁
        run: |
          COVERAGE=$(python -c "import xml.etree.ElementTree as ET; tree = ET.parse('reports/coverage.xml'); root = tree.getroot(); print(float(root.attrib['line-rate']) * 100)")
          echo "覆盖率: ${COVERAGE}%"
          if (( $(echo "$COVERAGE < 80" | bc -l) )); then
            echo "覆盖率低于 80% 门禁阈值，流水线失败"
            exit 1
          fi

  # ========== Stage 3: 集成测试 ==========
  integration-test:
    name: 集成测试
    needs: unit-test
    runs-on: ubuntu-latest
    services:
      # 启动 PostgreSQL 服务容器
      postgres:
        image: postgres:15-alpine
        env:
          POSTGRES_DB: test_db
          POSTGRES_USER: test_user
          POSTGRES_PASSWORD: test_pass
        ports:
          - 5432:5432
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5
    env:
      DATABASE_URL: postgresql://test_user:test_pass@localhost:5432/test_db
      REDIS_URL: redis://localhost:6379/0
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: ${{ env.PYTHON_VERSION }}
      - name: 安装依赖
        run: pip install -r requirements.txt
      - name: 数据库迁移
        run: alembic upgrade head
      - name: 运行集成测试
        run: |
          pytest tests/integration/ \
            -v \
            --junitxml=reports/junit-integration.xml
      - name: 上传集成测试报告
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: integration-test-reports
          path: reports/

  # ========== Stage 4: E2E 测试 ==========
  e2e-test:
    name: 端到端测试
    needs: integration-test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: ${{ env.PYTHON_VERSION }}
      - name: 安装依赖
        run: |
          pip install -r requirements.txt
          pip install playwright
          playwright install chromium
      - name: 启动测试环境
        run: docker-compose -f docker-compose.test.yml up -d
      - name: 等待服务就绪
        run: |
          timeout 60 bash -c 'until curl -s http://localhost:8000/health; do sleep 2; done'
      - name: 运行 E2E 测试
        run: |
          pytest tests/e2e/ \
            -v \
            --junitxml=reports/junit-e2e.xml
      - name: 上传 E2E 报告与截图
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: e2e-test-reports
          path: |
            reports/
            tests/e2e/screenshots/
      - name: 清理测试环境
        if: always()
        run: docker-compose -f docker-compose.test.yml down

  # ========== Stage 5: 报告聚合 ==========
  report:
    name: 测试报告聚合
    needs: [unit-test, integration-test, e2e-test]
    if: always()
    runs-on: ubuntu-latest
    steps:
      - name: 下载所有报告
        uses: actions/download-artifact@v4
        with:
          path: all-reports/

      - name: 聚合报告摘要
        run: |
          echo "## 测试执行摘要" >> $GITHUB_STEP_SUMMARY
          echo "" >> $GITHUB_STEP_SUMMARY
          echo "| 阶段 | 状态 |" >> $GITHUB_STEP_SUMMARY
          echo "|------|------|" >> $GITHUB_STEP_SUMMARY
          echo "| 代码检查 | ${{ needs.lint.result == 'success' && '✅ 通过' || '❌ 失败' }} |" >> $GITHUB_STEP_SUMMARY
          echo "| 单元测试 | ${{ needs.unit-test.result == 'success' && '✅ 通过' || '❌ 失败' }} |" >> $GITHUB_STEP_SUMMARY
          echo "| 集成测试 | ${{ needs.integration-test.result == 'success' && '✅ 通过' || '❌ 失败' }} |" >> $GITHUB_STEP_SUMMARY
          echo "| E2E 测试 | ${{ needs.e2e-test.result == 'success' && '✅ 通过' || '❌ 失败' }} |" >> $GITHUB_STEP_SUMMARY

  # ========== Stage 6: 部署门禁 + 部署 ==========
  deploy-staging:
    name: 部署到测试环境
    needs: [unit-test, integration-test]
    if: github.ref == 'refs/heads/develop' && github.event_name == 'push'
    runs-on: ubuntu-latest
    environment:
      name: staging
      url: https://staging.shop.test
    steps:
      - uses: actions/checkout@v4
      - name: 构建 Docker 镜像
        run: |
          docker build -t ${{ env.REGISTRY }}/${{ env.IMAGE_NAME }}:staging .
          docker push ${{ env.REGISTRY }}/${{ env.IMAGE_NAME }}:staging
      - name: 部署到测试环境
        run: |
          echo "执行部署命令..."
          # kubectl set image deployment/shop-app shop-app=${{ env.REGISTRY }}/${{ env.IMAGE_NAME }}:staging

  deploy-production:
    name: 部署到生产环境
    needs: [deploy-staging]
    if: github.ref == 'refs/heads/main' && github.event_name == 'push'
    runs-on: ubuntu-latest
    environment:
      name: production
      url: https://shop.example.com
    steps:
      - uses: actions/checkout@v4
      - name: 构建生产镜像
        run: |
          docker build -t ${{ env.REGISTRY }}/${{ env.IMAGE_NAME }}:${{ github.sha }} .
          docker tag ${{ env.REGISTRY }}/${{ env.IMAGE_NAME }}:${{ github.sha }} ${{ env.REGISTRY }}/${{ env.IMAGE_NAME }}:latest
          docker push ${{ env.REGISTRY }}/${{ env.IMAGE_NAME }}:${{ github.sha }}
          docker push ${{ env.REGISTRY }}/${{ env.IMAGE_NAME }}:latest
      - name: 部署到生产环境
        run: |
          echo "执行生产部署..."

  # ========== Stage 7: 通知 ==========
  notify:
    name: 通知团队
    needs: [deploy-staging, deploy-production]
    if: always()
    runs-on: ubuntu-latest
    steps:
      - name: 钉钉通知
        run: |
          STATUS="${{ needs.deploy-staging.result == 'success' && '成功' || '失败' }}"
          curl -X POST "${{ secrets.DINGTALK_WEBHOOK }}" \
            -H 'Content-Type: application/json' \
            -d "{
              \"msgtype\": \"markdown\",
              \"markdown\": {
                \"title\": \"部署通知\",
                \"text\": \"## 部署通知\\n\"
                          \"**项目:** ${{ github.repository }}\\n\"
                          \"**分支:** ${{ github.ref_name }}\\n\"
                          \"**状态:** ${STATUS}\\n\"
                          \"**提交:** ${{ github.event.head_commit.message }}\\n\"
                          \"**链接:** [查看详情](${{ github.server_url }}/${{ github.repository }}/actions/runs/${{ github.run_id }})\"
              }
            }"
```

### 实操 2：Artifact 制品管理

```yaml
# 上传制品
- name: 上传测试报告
  uses: actions/upload-artifact@v4
  with:
    name: test-reports-${{ github.run_number }}
    path: |
      reports/junit-*.xml
      reports/coverage.xml
      reports/htmlcov/
    retention-days: 30   # 保留天数（1-90）
    if-no-files-found: warn  # ignore/warn/error

# 下载制品
- name: 下载制品
  uses: actions/download-artifact@v4
  with:
    name: test-reports-${{ github.run_number }}
    path: downloaded-reports/

# 跨 Job 传递制品（通过 outputs）
jobs:
  build:
    runs-on: ubuntu-latest
    outputs:
      image-tag: ${{ steps.meta.outputs.version }}
    steps:
      - id: meta
        run: echo "version=$(git rev-parse --short HEAD)" >> $GITHUB_OUTPUT

  deploy:
    needs: build
    runs-on: ubuntu-latest
    steps:
      - run: echo "部署镜像标签: ${{ needs.build.outputs.image-tag }}"
```

### 实操 5：完整的 ShopTest 流水线

```yaml
# .github/workflows/shop-test.yml

name: ShopTest CI/CD

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

env:
  PYTHON_VERSION: '3.11'

jobs:
  # 阶段 1-4（lint/unit/integration/e2e）同上
  # ...

  # 冒烟测试（部署后验证）
  smoke-test:
    name: 冒烟测试
    needs: deploy-staging
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python.version: ${{ env.PYTHON_VERSION }}
      - name: 安装依赖
        run: pip install requests
      - name: 执行冒烟测试
        env:
          BASE_URL: https://staging.shop.test
        run: |
          python -c "
          import requests, sys
          tests = [
              ('GET', '/health', 200),
              ('GET', '/api/products', 200),
              ('POST', '/api/auth/login', 401),
          ]
          failed = 0
          for method, path, expected in tests:
              resp = requests.request(method, f'{sys.argv[1]}{path}')
              if resp.status_code != expected:
                  print(f'FAIL: {method} {path} -> {resp.status_code} (expected {expected})')
                  failed += 1
              else:
                  print(f'OK: {method} {path} -> {resp.status_code}')
          sys.exit(failed if failed else 0)
          " $BASE_URL
```

## 常见坑

- `needs` 仅支持同一 workflow 文件内的 Job 依赖，跨文件需使用 `workflow_run` 触发器
- Artifact 在工作流运行结束后才能下载，同一运行中的 Job 之间传递使用 `upload-artifact` + `download-artifact`
- `environment` 配置 Protection rules 后，流水线会暂停等待审批，需在 GitHub UI 手动批准
- Docker 镜像构建建议使用缓存：`docker buildx build --cache-from` 配合 GitHub Actions cache
- 通知渠道建议配置 `if: always()` 或 `if: failure()`，避免成功时也发送造成信息过载
- 覆盖率门禁阈值需根据项目实际设定，过高的阈值会导致频繁阻塞合并
