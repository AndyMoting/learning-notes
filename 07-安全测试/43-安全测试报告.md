# 43-安全测试报告
> 课时：60 min | 难度：★★★

## 学习目标
- 掌握安全测试报告的标准结构与必备要素
- 能使用 CVSS v3.1 评分系统对漏洞进行量化评级
- 能根据风险等级制定合理的修复优先级与建议
- 能独立完成一份完整的安全测试报告

## 核心概念

### 安全测试报告结构

```
1. 封面与版本信息
2. 执行摘要（Executive Summary）
3. 测试范围与方法
4. 漏洞详情（核心部分）
5. 风险统计与分布
6. 修复建议与优先级
7. 附录（工具列表、测试账号、原始数据）
```

### 报告各部分详解

**1. 封面与版本信息**
```
项目名称：ShopTest 安全测试报告
委托方：XXX 科技有限公司
测试方：XXX 测试团队
报告版本：v1.0
发布日期：2024-01-15
密级：机密
```

**2. 执行摘要**
```
本次安全测试覆盖 ShopTest 平台的全部核心功能模块，共发现安全漏洞 12 个。
其中：严重（Critical）1 个、高危（High）3 个、中危（Medium）5 个、低危（Low）3 个。
最严重漏洞为 SQL 注入（A03），可导致数据库全部数据泄露，建议立即修复。
整体安全评级：C（存在高危漏洞，需限期整改）。
```

**3. 测试范围与方法**
```
测试范围：
- 目标系统：https://shop.test.example.com
- 测试时间：2024-01-10 至 2024-01-14
- 测试账号：test_admin / test_user（由委托方提供）
- 排除范围：第三方支付接口、CDN 服务

测试方法：
- OWASP Testing Guide v4.2
- 黑盒测试 + 灰盒测试
- 自动化扫描（OWASP ZAP + sqlmap）
- 手动渗透测试（Burp Suite）
```

### CVSS v3.1 评分方法论

**CVSS（Common Vulnerability Scoring System）** 是业界通用的漏洞严重程度量化评分系统，v3.1 版本评分范围 0.0-10.0。

**评分维度：**

| 维度 | 指标 | 可选值 |
|------|------|--------|
| 攻击向量 (AV) | 漏洞利用的网络条件 | Network / Adjacent / Local / Physical |
| 攻击复杂度 (AC) | 利用所需条件的可控性 | Low / High |
| 所需权限 (PR) | 利用前需要的权限级别 | None / Low / High |
| 用户交互 (UI) | 是否需要用户参与 | None / Required |
| 影响范围 (S) | 漏洞是否影响其他组件 | Changed / Unchanged |
| 机密性影响 (C) | 对数据保密性的影响 | None / Low / High |
| 完整性影响 (I) | 对数据完整性的影响 | None / Low / High |
| 可用性影响 (A) | 对系统可用性的影响 | None / Low / High |

**评分计算示例：**
```
SQL 注入漏洞：
AV:N（网络可访问） AC:L（低复杂度） PR:N（无需权限） UI:N（无需交互）
S:C（影响范围扩大） C:H（完全泄露） I:H（完全篡改） A:H（完全不可用）

CVSS 向量：CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H
CVSS 评分：10.0（Critical）
```

**风险等级映射：**

| CVSS 评分 | 风险等级 | 修复时限 |
|-----------|----------|----------|
| 9.0 - 10.0 | Critical（严重） | 24 小时内 |
| 7.0 - 8.9 | High（高危） | 7 天内 |
| 4.0 - 6.9 | Medium（中危） | 30 天内 |
| 0.1 - 3.9 | Low（低危） | 90 天内 |
| 0.0 | Info（信息） | 无需修复 |

### 漏洞详情模板

```markdown
### VULN-001：用户登录接口 SQL 注入

**风险等级：** Critical（CVSS 10.0）
**OWASP 分类：** A03 - 注入
**发现日期：** 2024-01-12
**发现人：** 张三
**影响组件：** /api/auth/login

**漏洞描述：**
登录接口的 username 参数未进行参数化处理，攻击者可通过构造恶意输入
绕过身份验证或直接获取数据库全部数据。

**复现步骤：**
1. 访问 https://shop.test.example.com/login
2. 在用户名字段输入：' OR '1'='1' --
3. 密码字段输入任意值
4. 点击登录 → 成功以第一个用户身份登录

**POC（概念验证）：**
```http
POST /api/auth/login HTTP/1.1
Content-Type: application/json

{"username": "' OR '1'='1' --", "password": "anything"}
```

**影响分析：**
- 攻击者无需凭证即可登录任意账户
- 可通过 UNION 注入导出全部用户数据（含密码哈希）
- 可通过注入执行系统命令（取决于数据库权限）

**修复建议：**
1. 使用参数化查询（PreparedStatement）替代字符串拼接
2. 对所有输入进行白名单校验（用户名仅允许字母数字）
3. 数据库账户遵循最小权限原则，禁止 FILE/PROCESS 权限
4. 部署 WAF 规则拦截常见 SQL 注入 Payload

**参考资料：**
- OWASP SQL Injection: https://owasp.org/Top10/A03_2021-Injection/
- CWE-89: https://cwe.mitre.org/data/definitions/89.html
```

## 动手实操

### 实操 1：CVSS 评分练习

```
场景 1：某内部管理系统存在反射型 XSS，需用户点击恶意链接触发，
       系统部署在内网，仅影响当前用户会话。
评分：AV:N/AC:L/PR:N/UI:R/S:C/C:L/I:L/A:N → 6.1 (Medium)

场景 2：某电商平台订单接口存在 IDOR，可遍历所有订单信息，
       无需登录即可访问。
评分：AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N → 7.5 (High)

场景 3：某系统使用 MD5 存储密码，数据库泄露后可被彩虹表破解。
评分：AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N → 7.5 (High)
（注：实际评分需结合完整影响范围分析）
```

### 实操 3：使用 CVSS 计算器

```python
# 使用 cvss 库计算评分
# pip install cvss

from cvss import CVSS3

# SQL 注入示例
vector = "CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H"
c = CVSS3(vector)
print(f"Base Score: {c.base_score}")        # 10.0
print(f"Severity: {c.severities()}")        # ['Critical']
print(f"Vector: {c.vector}")                # CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H

# 水平越权示例
vector2 = "CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N"
c2 = CVSS3(vector2)
print(f"Base Score: {c2.base_score}")       # 7.5
print(f"Severity: {c2.severities()}")       # ['High']
```

## 常见坑

- CVSS 评分中 PR（所需权限）在 v3.1 中根据影响范围 (S) 变化有不同取值，S:Changed 时 PR 权重更高
- 报告中的复现步骤必须精确到可直接复现，模糊描述（"在某些情况下可能触发"）会导致开发无法修复
- 修复建议需具体可执行（"加强安全防护" → 不合格；"使用参数化查询替换字符串拼接" → 合格）
- 风险等级不能全部标为 Critical，需根据实际影响区分优先级
- 报告中需明确标注测试范围与排除范围，避免责任纠纷
- 漏洞编号（VULN-XXX）需保持唯一且贯穿整个修复周期，便于跟踪
