# 42-安全测试工具
> 课时：75 min | 难度：★★★★

## 学习目标
- 掌握 Bandit、sqlmap、OWASP ZAP、Burp Suite 四款核心安全测试工具的安装与基本使用
- 能根据测试场景选择合适的工具并执行自动化安全检测
- 理解各工具的适用范围与局限性
- 遵守安全测试法律边界，仅在授权系统上执行测试

## 核心概念

### 工具分类与定位

| 工具 | 类型 | 语言/平台 | 核心能力 | 适用阶段 |
|------|------|-----------|----------|----------|
| Bandit | SAST（静态分析） | Python | 代码层面发现安全缺陷 | 开发阶段 |
| sqlmap | DAST（注入专项） | Python | SQL 注入自动化检测与利用 | 测试阶段 |
| OWASP ZAP | DAST（综合扫描） | Java | Web 应用自动化漏洞扫描 | 测试阶段 |
| Burp Suite | 手动渗透测试 | Java | 拦截/重放/修改 HTTP 请求 | 测试阶段 |

### 法律声明

> **安全测试工具仅可用于已获得书面授权的系统。未经授权对任何系统执行渗透测试、漏洞扫描、注入攻击均违反《网络安全法》《数据安全法》等相关法律法规。测试前必须取得系统所有者的明确授权，并约定测试范围与时间窗口。**

## Bandit — Python 静态代码分析

### 安装
```bash
pip install bandit
```

### 基本使用
```bash
# 扫描单个文件
bandit app.py

# 扫描整个项目目录
bandit -r ./src/

# 指定输出格式（支持 csv、json、xml、html、txt）
bandit -r ./src/ -f json -o report.json

# 指定最低严重级别（LOW / MEDIUM / HIGH）
bandit -r ./src/ -l  # 仅报告 HIGH 级别

# 跳过特定测试（通过测试 ID）
bandit -r ./src/ -s B301,B302

# 指定配置文件
bandit -r ./src/ -c bandit.yaml
```

### 配置文件 bandit.yaml
```yaml
skips: []
assert_used:
  skips: ['*/test_*.py', '*/tests/*']
```

### 常见检测项
| 测试 ID | 检测内容 | 严重级别 |
|---------|----------|----------|
| B102 | exec() 使用 | HIGH |
| B105 | 硬编码密码字符串 | MEDIUM |
| B301 | 不安全的反序列化 (pickle) | MEDIUM |
| B303 | 不安全的哈希算法 (MD5/SHA1) | HIGH |
| B307 | eval() 使用 | HIGH |
| B311 | 伪随机数生成器 | LOW |
| B501 | 不验证 SSL 证书 | HIGH |
| B602 | shell=True 调用系统命令 | HIGH |
| B605 | 从输入启动进程 | MEDIUM |

### 输出示例
```
>> Issue: [B303:md5] Use of insecure MD2, MD4, MD5, or SHA1 hash function.
   Severity: High   Confidence: High
   Location: utils/crypto.py:12
   More Info: https://bandit.readthedocs.io/en/latest/...

--------------------------------------------------
Code:
11  def hash_password(password):
12      return hashlib.md5(password.encode()).hexdigest()
```

## sqlmap — SQL 注入自动化

### 安装
```bash
# 方式 1：pip 安装
pip install sqlmap

# 方式 2：源码安装
git clone --depth 1 https://github.com/sqlmapproject/sqlmap.git
cd sqlmap && python sqlmap.py --version
```

### 基本使用
```bash
# 基础检测（GET 参数）
sqlmap -u "http://target.com/page?id=1"

# POST 注入（从文件读取请求）
sqlmap -r request.txt --batch

# 指定数据库类型
sqlmap -u "http://target.com/page?id=1" --dbms=mysql

# 枚举数据库
sqlmap -u "http://target.com/page?id=1" --dbs

# 枚举指定数据库的表
sqlmap -u "http://target.com/page?id=1" -D target_db --tables

# 导出指定表数据
sqlmap -u "http://target.com/page?id=1" -D target_db -T users --dump

# 获取 Shell（高级，需高权限）
sqlmap -u "http://target.com/page?id=1" --os-shell

# 设置检测级别与风险等级
sqlmap -u "http://target.com/page?id=1" --level=5 --risk=3

# 使用代理（配合 Burp Suite 观察请求）
sqlmap -u "http://target.com/page?id=1" --proxy="http://127.0.0.1:8080"
```

### 关键参数说明
| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--level` | 检测深度（1-5），越高覆盖越多注入点 | 1 |
| `--risk` | 风险等级（1-3），越高使用越危险的 Payload | 1 |
| `--batch` | 自动选择默认选项，无需交互 | 否 |
| `--threads` | 并发线程数 | 1 |
| `--tamper` | 使用混淆脚本绕过 WAF | 无 |
| `--technique` | 指定注入类型（B/E/U/S/T/Q） | 全部 |

### 常用 Tamper 脚本
```bash
# 绕过简单 WAF
sqlmap -u "http://target.com/page?id=1" --tamper=space2comment,charencode

# 常用 tamper 列表
# space2comment    → 空格替换为 /**/
# charencode       → URL 编码
# randomcase       → 随机大小写
# between          → 用 BETWEEN 替换 >
# equaltolike      → 用 LIKE 替换 =
```

## OWASP ZAP — 动态应用安全扫描

### 安装
```bash
# 方式 1：Docker 运行
docker pull owasp/zap2docker-stable
docker run -u zap -p 8080:8080 owasp/zap2docker-stable zap.sh -daemon -port 8080

# 方式 2：系统包管理器（macOS）
brew install --cask owasp-zap

# 方式 3：下载安装包
# 访问 https://www.zaproxy.org/download/ 下载对应平台安装包
```

### 基本使用流程
```
1. 启动 ZAP → 选择 "No, I do not want to persist..."（临时会话）
2. 配置浏览器代理指向 ZAP（默认 127.0.0.1:8080）
3. 在 ZAP 中输入目标 URL → 点击 "Attack" 启动自动扫描
4. 扫描完成后查看 Alerts 面板
5. 导出报告：Report → Generate Report → HTML/JSON/XML
```

### 核心功能
| 功能 | 说明 |
|------|------|
| Automated Scanner | 自动爬取并扫描所有页面 |
| Manual Explore | 手动浏览时被动扫描 |
| Fuzzer | 对指定请求参数进行模糊测试 |
| Breakpoints | 拦截并修改请求/响应 |
| Spider | 自动爬取网站结构 |
| AJAX Spider | 支持 JavaScript 渲染的爬取 |

### ZAP API 调用
```bash
# 启动 ZAP Daemon 后通过 API 调用
# 启动扫描
curl "http://localhost:8080/JSON/ascan/action/scan/?url=http://target.com"

# 查看扫描进度
curl "http://localhost:8080/JSON/ascan/view/status/"

# 获取告警
curl "http://localhost:8080/JSON/core/view/alerts/"

# 生成 HTML 报告
curl "http://localhost:8080/OTHER/core/other/htmlreport/" -o report.html
```

## Burp Suite — 手动渗透测试平台

### 安装
```bash
# 下载 Community Edition（免费）
# 访问 https://portswigger.net/burp/communitydownload

# 启动
java -jar burpsuite_community.jar

# 配置浏览器代理：127.0.0.1:8080
# 安装 CA 证书：访问 http://burpsuite 下载并安装
```

### 核心模块
| 模块 | 功能 |
|------|------|
| Proxy | 拦截、查看、修改 HTTP/HTTPS 请求与响应 |
| Repeater | 手动修改并重放请求，观察响应变化 |
| Intruder | 自动化参数爆破（枚举、模糊测试） |
| Decoder | 编码/解码（Base64、URL、Hex、HTML） |
| Comparer | 对比两次请求/响应的差异 |
| Sequencer | 分析 Token 的随机性质量 |

### Proxy 模块使用
```
1. Proxy → Intercept → Intercept is on
2. 浏览器发起请求 → 请求被 Burp 拦截
3. 检查/修改请求内容 → Forward 放行 / Drop 丢弃
4. 关闭拦截：Intercept is off（被动监听模式）
```

### Intruder 模块使用
```
1. 在 Proxy 中拦截目标请求 → 右键 Send to Intruder
2. Intruder → Positions → 用 § 符号标记要爆破的参数
3. 选择攻击类型：
   - Sniper：单参数逐个替换
   - Battering ram：所有参数使用相同值
   - Pitchfork：多参数同步替换（字典长度需一致）
   - Cluster bomb：多参数笛卡尔积组合
4. Payloads → 加载字典或手动输入
5. Start Attack → 分析响应差异（状态码、长度、响应时间）
```

### Repeater 模块使用
```
1. 拦截请求 → 右键 Send to Repeater
2. 在 Repeater 中修改参数值
3. 点击 Send → 查看响应
4. 反复修改测试，观察不同输入的响应差异
```

## 工具对比与选型

| 场景 | 推荐工具 | 原因 |
|------|----------|------|
| 代码提交前快速检查 | Bandit | 轻量、集成 CI、零配置 |
| 疑似 SQL 注入确认 | sqlmap | 覆盖全面、Payload 丰富 |
| 全站自动化扫描 | OWASP ZAP | 免费、覆盖广、支持 API |
| 复杂业务逻辑测试 | Burp Suite | 手动灵活、可精细控制 |
| 绕过 WAF 测试 | sqlmap + tamper | 内置大量混淆脚本 |
| 认证流程测试 | Burp Suite | 会话管理、Cookie 操作便捷 |

## 动手实操

### 实操 1：Bandit 扫描 Python 项目

```bash
# 创建测试项目
mkdir security_demo && cd security_demo

# 创建含安全缺陷的示例文件
cat > app.py << 'EOF'
import hashlib
import pickle
import os

def hash_password(password):
    return hashlib.md5(password.encode()).hexdigest()

def load_data(data):
    return pickle.loads(data)

def run_command(user_input):
    os.system("ping -c 1 " + user_input)
EOF

# 执行扫描
bandit -r . -f json -o bandit_report.json

# 查看结果
cat bandit_report.json | python -m json.tool
```

### 实操 2：sqlmap 检测注入点

```bash
# 使用 DVWA（Damn Vulnerable Web Application）作为靶场
# 假设 DVWA 已部署在本地 http://localhost/dvwa/

# 基础检测
sqlmap -u "http://localhost/dvwa/vulnerabilities/sqli/?id=1&Submit=Submit" \
  --cookie="security=low; PHPSESSID=xxx" \
  --batch --dbs

# 获取当前数据库
sqlmap -u "http://localhost/dvwa/vulnerabilities/sqli/?id=1&Submit=Submit" \
  --cookie="security=low; PHPSESSID=xxx" \
  --current-db
```

### 实操 3：ZAP 自动化扫描脚本

```python
from zapv2 import ZAPv2
import time

# 连接 ZAP API
zap = ZAPv2(proxies={'http': 'http://127.0.0.1:8080', 'https': 'http://127.0.0.1:8080'})

target = "http://shop.test"

# 启动 Spider
print("Starting Spider...")
scan_id = zap.spider.scan(target)
while int(zap.spider.status(scan_id)) < 100:
    print(f"Spider progress: {zap.spider.status(scan_id)}%")
    time.sleep(5)

# 启动主动扫描
print("Starting Active Scan...")
scan_id = zap.ascan.scan(target)
while int(zap.ascan.status(scan_id)) < 100:
    print(f"Scan progress: {zap.ascan.status(scan_id)}%")
    time.sleep(10)

# 获取结果
alerts = zap.core.alerts()
for alert in alerts:
    print(f"[{alert['risk']}] {alert['name']} - {alert['url']}")

# 生成报告
report = zap.core.htmlreport()
with open("zap_report.html", "w") as f:
    f.write(report)
```

## 常见坑

- sqlmap 默认 `--level=1 --risk=1` 覆盖范围有限，生产测试建议 `--level=3 --risk=2`
- ZAP 扫描需要配置正确的会话 Cookie，否则无法扫描需要登录的页面
- Burp Suite Community Edition 的 Intruder 有速率限制，不适合大规模爆破
- Bandit 仅扫描 Python 代码，不覆盖依赖库中的漏洞（需配合 pip-audit）
- 所有工具在 Docker 中运行时需注意网络模式，确保能访问目标系统
- 自动化扫描结果存在误报率（通常 10%-30%），关键漏洞必须人工验证
