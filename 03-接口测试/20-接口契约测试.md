## 核心概念

### 什么是契约测试

契约测试验证服务提供者与消费者之间是否遵守预定义的数据格式约定。相比集成测试，契约测试——

| 维度 | 集成测试 | 契约测试 |
|---|---|---|
| 速度 | 慢（需真实环境） | 快（可独立运行） |
| 依赖 | 上下游服务均需可用 | 只需契约文档 |
| 发现时机 | 集成阶段 | 开发阶段 |
| 维护成本 | 高 | 中 |

**核心价值**：在不启动外部系统的前提下，验证 API 行为与文档描述一致。

### OpenAPI 规范结构

```yaml
openapi: 3.0.3
info:
  title: ShopTest API
  version: "1.0"
paths:
  /products:
    get:
      summary: 获取商品列表
      parameters:
        - name: category
          in: query
          schema:
            type: string
      responses:
        '200':
          description: 成功
          content:
            application/json:
              schema:
                type: array
                items:
                  $ref: '#/components/schemas/Product'
components:
  schemas:
    Product:
      type: object
      required: [id, name, price]
      properties:
        id:
          type: integer
        name:
          type: string
        price:
          type: number
```

关键字段说明：

| 字段 | 用途 |
|---|---|
| `paths` | 定义所有端点及 HTTP 方法 |
| `parameters` | Query / Path / Header 参数声明 |
| `responses` | 各状态码对应的响应结构 |
| `components/schemas` | 可复用的数据模型定义 |
| `required` | 必填字段约束 |

### Diff 测试（回归测试）

Diff 测试通过对比当前 API 响应与基线响应，发现非预期的字段变更：

| 变更类型 | 严重程度 | 示例 |
|---|---|---|
| 字段删除 | 高 | 响应中移除 `discount` 字段 |
| 字段类型变更 | 高 | `price` 从 `number` 变为 `string` |
| 新增字段 | 低 | 响应增加 `rating` 字段 |
| 必填变可选 | 中 | `email` 从 required 变为可选 |

### 自定义检查

```python
# conftest.py
import schemathesis

@schemathesis.check
def response_time_check(case, response):
    """检查响应时间是否在 500ms 以内"""
    assert response.elapsed.total_seconds() < 0.5, \
        f"Response too slow: {response.elapsed.total_seconds()}s for {case.request.url}"

@schemathesis.check
def no_sensitive_data_leak(case, response):
    """检查响应中不应包含敏感字段"""
    if response.status_code == 200:
        body = response.json()
        sensitive_fields = ["password", "secret", "token", "credit_card"]
        for field in sensitive_fields:
            assert field not in str(body).lower(), \
                f"Sensitive field '{field}' leaked in response"
```

### Hooks 扩展

```python
# hooks.py
import schemathesis

@schemathesis.hook
def before_generate_query(context, strategy):
    """自定义 Query 参数生成策略"""
    return strategy.filter(lambda x: x.get("page", 1) > 0)

@schemathesis.hook
def after_call(case, response):
    """请求后处理 - 记录响应日志"""
    print(f"[{case.method}] {case.path} -> {response.status_code}")

@schemathesis.hook
def add_headers(case, headers):
    """动态添加请求鉴权头"""
    headers["Authorization"] = f"Bearer {get_dynamic_token()}"
    return headers
```

### CI 集成

**GitHub Actions 配置**：

```yaml
# .github/workflows/contract-test.yml
name: Contract Tests

on:
  pull_request:
    branches: [main]
  push:
    branches: [main]

jobs:
  schemathesis:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.11'

      - name: Install dependencies
        run: pip install schemathesis httpx

      - name: Start API server
        run: |
          uvicorn app:app --host 0.0.0.0 --port 8000 &
          sleep 3

      - name: Run contract tests
        run: |
          st run http://localhost:8000/openapi.json \
            --checks=all \
            --junit-xml=results.xml \
            --hypothesis-max-examples=100

      - name: Upload results
        uses: actions/upload-artifact@v4
        if: always()
        with:
          name: contract-test-results
          path: results.xml
```

### ShopTest 契约测试实例

**OpenAPI 规范片段** (`shoptest-api.yaml`)：

```yaml
openapi: 3.0.3
info:
  title: ShopTest API
  version: "1.0.0"
servers:
  - url: http://localhost:8000/api
paths:
  /products:
    get:
      operationId: listProducts
      parameters:
        - name: category
          in: query
          schema:
            type: string
            enum: [electronics, clothing, food]
        - name: page
          in: query
          schema:
            type: integer
            minimum: 1
            default: 1
      responses:
        '200':
          description: 商品列表
          content:
            application/json:
              schema:
                type: object
                required: [items, total, page]
                properties:
                  items:
                    type: array
                    items:
                      $ref: '#/components/schemas/Product'
                  total:
                    type: integer
                  page:
                    type: integer
        '400':
          description: 参数错误

    post:
      operationId: createProduct
      requestBody:
        required: true
        content:
          application/json:
            schema:
              $ref: '#/components/schemas/ProductInput'
      responses:
        '201':
          description: 创建成功
        '422':
          description: 校验失败

  /products/{productId}:
    get:
      operationId: getProduct
      parameters:
        - name: productId
          in: path
          required: true
          schema:
            type: integer
      responses:
        '200':
          description: 商品详情
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/Product'
        '404':
          description: 商品不存在

components:
  schemas:
    Product:
      type: object
      required: [id, name, price]
      properties:
        id:
          type: integer
          example: 1
        name:
          type: string
          example: 无线键盘
        price:
          type: number
          format: float
          example: 299.00
        category:
          type: string
          enum: [electronics, clothing, food]
        stock:
          type: integer
          minimum: 0

    ProductInput:
      type: object
      required: [name, price]
      properties:
        name:
          type: string
          minLength: 1
          maxLength: 100
        price:
          type: number
          minimum: 0.01
        category:
          type: string
        stock:
          type: integer
          minimum: 0
```

### Diff 测试脚本

```python
"""API Diff 测试 - 检测响应变更"""
import requests
import json
import hashlib
import difflib
from pathlib import Path

BASELINE_FILE = "api_baseline.json"

def capture_baseline(base_url: str) -> dict:
    """捕获当前 API 响应作为基线"""
    endpoints = {
        "products_list": "/products",
        "product_detail": "/products/1",
    }

    baseline = {}
    for name, path in endpoints.items():
        resp = requests.get(f"{base_url}{path}")
        baseline[name] = {
            "status": resp.status_code,
            "keys": sorted(resp.json().keys()) if resp.status_code == 200 else [],
            "body_hash": hashlib.md5(resp.content).hexdigest(),
        }

    Path(BASELINE_FILE).write_text(json.dumps(baseline, indent=2, ensure_ascii=False))
    print("Baseline captured.")

def run_diff_test(base_url: str) -> bool:
    """对比当前响应与基线"""
    baseline = json.loads(Path(BASELINE_FILE).read_text())
    has_changes = False

    for name, expected in baseline.items():
        path = "/" + name.replace("_", "/") if "detail" in name else "/products"
        resp = requests.get(f"{base_url}{path}")

        # 检查状态码
        if resp.status_code != expected["status"]:
            print(f"[CHANGED] {name}: status {expected['status']} -> {resp.status_code}")
            has_changes = True

        # 检查响应字段
        current_keys = sorted(resp.json().keys()) if resp.status_code == 200 else []
        if current_keys != expected["keys"]:
            added = set(current_keys) - set(expected["keys"])
            removed = set(expected["keys"]) - set(current_keys)
            if added:
                print(f"[WARN] {name}: new fields added: {added}")
            if removed:
                print(f"[BREAKING] {name}: fields removed: {removed}")
                has_changes = True

        current_hash = hashlib.md5(resp.content).hexdigest()
        if current_hash != expected["body_hash"]:
            print(f"[INFO] {name}: body content changed (hash mismatch)")

    if not has_changes:
        print("No breaking changes detected.")
    return has_changes

if __name__ == "__main__":
    BASE = "http://localhost:8000/api"
    # 首次运行取消下面注释以建立基线
    # capture_baseline(BASE)
    run_diff_test(BASE)
```

## 常见坑

1. **规范与实际不一致**：OpenAPI 文档未随代码更新，导致契约测试误报——需在代码评审环节将规范同步纳入检查
2. **默认值缺失**：规范中未声明默认参数的边界行为，客户端拿到 null 值后异常
3. **枚举值溢出**：后端新增枚举值但规范未更新，旧版本客户端反序列化失败
4. **schemathesis 认证**：未在 hook 中配置鉴权头，所有受保护端点返回 401 导致覆盖率低
5. **过度依赖自动生成**：自动生成的用例覆盖参数组合，但业务逻辑分支需手动补充
6. **Diff 测试基线管理**：基线文件未纳入版本控制或未设定基线更新审批流程
