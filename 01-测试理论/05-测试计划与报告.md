# 05-测试计划与报告

> 课时：45 min | 难度：★★☆☆☆

## 学习目标

1. 掌握测试计划六要素的定义与编写方法
2. 掌握测试报告的结构与编写规范
3. 能够独立编写可复用的测试计划与测试报告模板

## 核心概念

### 测试计划六要素

| 要素 | 说明 | 示例 |
|------|------|------|
| 背景（Background） | 项目概述、测试目标、测试目的说明 | 电商平台V2.3版本上线前验证 |
| 目标（Objectives） | 测试活动要达到的具体目标 | 核心交易链路缺陷发现率 ≥ 95% |
| 范围（Scope） | 测试覆盖内容与排除内容的明确边界 | 包含下单/支付/退款流程；排除后台管理模块 |
| 资源（Resources） | 人力、工具、环境、数据等资源分配 | 3名测试人员、JMeter、预发布环境4节点 |
| 进度（Schedule） | 各阶段时间节点与里程碑 | 用例设计 3天 → 执行 5天 → 回归 2天 |
| 风险（Risk） | 潜在风险点及应对方案 | 第三方支付接口不稳定 → Mock服务降级 |

### 测试报告结构

| 章节 | 内容 |
|------|------|
| 概述（Overview） | 测试目的、测试时间、测试版本、参与人员 |
| 测试设计（Test Design） | 测试策略、测试范围、测试环境、测试工具 |
| 测试总结（Summary） | 用例执行情况、通过率、执行效率 |
| 缺陷汇总（Bug Summary） | 缺陷总数、严重分布、趋势图、遗留列表 |
| 测试结论（Conclusion） | 质量评估、是否通过、遗留风险说明 |

## 动手实操

### 测试计划模板

```markdown
# [项目名称] 测试计划

## 1. 背景
- 项目描述：
- 版本号：
- 测试目的：

## 2. 测试目标
- 验证核心功能正确性
- 性能达到预设指标
- 兼容性覆盖目标范围

## 3. 测试范围

### 包含（In Scope）
- [功能模块1]
- [功能模块2]

### 不包含（Out of Scope）
- [排除模块及原因]

## 4. 测试策略
| 测试类型 | 覆盖内容 | 工具/方法 |
|---------|---------|----------|
| 功能测试 | 核心业务流程 | 黑盒用例法 |
| 接口测试 | API层验证 | Postman + Charles |
| 性能测试 | 高并发场景 | JMeter |
| 兼容性测试 | 多浏览器/设备 | BrowserStack |

## 5. 资源分配
| 角色 | 人员 | 职责 |
|------|------|------|
| 测试负责人 | | 计划制定、进度把控 |
| 测试工程师 | | 用例编写与执行 |
| 开发代表 | | 缺陷修复 |

## 6. 进度安排
| 阶段 | 开始日期 | 结束日期 | 产出物 |
|------|---------|---------|--------|
| 需求评审 | | | 评审纪要 |
| 用例设计 | | | 测试用例集 |
| 用例评审 | | | 评审纪要 |
| 测试执行 | | | 缺陷列表 |
| 回归测试 | | | 回归报告 |
| 报告输出 | | | 测试报告 |

## 7. 风险与应对
| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|---------|
| 需求变更频繁 | 高 | 高 | 锁定基线版本、变更走评审 |
| 测试环境不稳定 | 中 | 高 | 准备备用环境、提前预约 |
| 测试数据不足 | 中 | 中 | 提前构造数据脚本 |

## 8. 准入/准出标准

### 准入条件
- 开发自测通过
- 冒烟测试通过率 100%
- 测试环境部署成功

### 准出条件
- 用例执行率 100%
- 通过率 ≥ 95%
- 严重缺陷全部修复
- 遗留问题有应对方案
```

## 常见坑

| 错误 | 说明 |
|------|------|
| 范围描述模糊 | "测试所有功能"无法衡量边界，应逐模块标注包含/排除 |
| 进度未留缓冲 | 未考虑缺陷修复与回归时间，导致进度失控 |
| 风险未分等级 | 所有风险同等对待，未按概率×影响排优先级 |
| 报告仅堆数字 | 只列通过率不分析原因，报告无决策参考价值 |
| 准出标准缺失 | 无明确通过条件，测试结束无依据 |
| 遗漏追溯矩阵 | 需求-用例-缺陷无关联，变更影响无法评估 |
