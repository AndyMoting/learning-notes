## 核心概念

### OSI 七层模型 vs TCP/IP 四层模型

| OSI 七层模型 | TCP/IP 四层模型 | 核心协议 | 关键功能 |
|--------------|----------------|---------|---------|
| 应用层（Application） | | HTTP/FTP/DNS/SMTP | 用户接口、应用服务 |
| 表示层（Presentation） | 应用层 | SSL/TLS/ASCII | 数据格式转换、加密 |
| 会话层（Session） | | NetBIOS/RPC | 会话建立与管理 |
| 传输层（Transport） | 传输层 | TCP/UDP | 端到端数据传输 |
| 网络层（Network） | 网络层 | IP/ICMP/ARP | 路由寻址、数据转发 |
| 数据链路层（Data Link） | 网络接口层 | Ethernet/PPP | 帧传输、MAC寻址 |
| 物理层（Physical） | | 双绞线/光纤 | 比特流物理传输 |

**记忆要点**：应用层（会话+表示+应用）→ 传输层（TCP/UDP）→ 网络层（IP）→ 链路层（物理+链路）

### HTTP 协议结构

**请求结构（Request）：**

```
POST /api/users HTTP/1.1                ← 请求行（Method + URL + Protocol）
Host: www.example.com                    ← 请求头（Headers）
Content-Type: application/json
Authorization: Bearer abc123
Content-Length: 54
                                         ← 空行（分隔头与体）
{"name":"test","password":"123456"}     ← 请求体（Body）
```

| 组成部分 | 说明 | 示例 |
|---------|------|------|
| Method | 请求方法 | GET/POST/PUT/DELETE/PATCH |
| URL | 资源地址 | `/api/v1/products?page=1` |
| Headers | 元信息 | Content-Type/Cookie/Authorization |
| Body | 请求数据（可选） | JSON/Form-data/XML |

**响应结构（Response）：**

```
HTTP/1.1 200 OK                          ← 状态行（Protocol + Status + Reason）
Content-Type: application/json           ← 响应头
Content-Length: 85
Set-Cookie: sessionid=xyz789
                                          ← 空行
{"code":0,"data":{"id":1,"name":"test"}}  ← 响应体
```

### HTTP 状态码

| 类别 | 含义 | 常见状态码 |
|------|------|----------|
| 1xx | 信息响应（接收继续处理） | 100 Continue、101 Switching Protocols |
| 2xx | 成功 | 200 OK、201 Created、204 No Content |
| 3xx | 重定向 | 301 Moved Permanently、302 Found、304 Not Modified |
| 4xx | 客户端错误 | 400 Bad Request、401 Unauthorized、403 Forbidden、404 Not Found、408 Request Timeout |
| 5xx | 服务器错误 | 500 Internal Server Error、502 Bad Gateway、503 Service Unavailable、504 Gateway Timeout |

**高频状态码详解：**

| 状态码 | 场景说明 |
|--------|---------|
| 200 | 标准成功响应 |
| 301 | 永久重定向，书签自动更新 |
| 302 | 临时重定向，每次重新请求原URL |
| 304 | 资源未修改，使用缓存 |
| 400 | 请求参数格式错误 |
| 401 | 未认证，需登录 |
| 403 | 已认证但无权限 |
| 404 | 资源不存在 |
| 500 | 服务器代码异常 |
| 502 | 网关收到无效响应 |
| 503 | 服务不可用（过载/维护） |

### TCP vs UDP

| 对比维度 | TCP | UDP |
|---------|-----|-----|
| 连接方式 | 面向连接（三次握手） | 无连接 |
| 可靠性 | 可靠传输（确认+重传+排序） | 不可靠传输 |
| 传输速度 | 较慢 | 较快 |
| 数据边界 | 无边界（字节流） | 有边界（数据报） |
| 适用场景 | 网页/邮件/文件传输 | 视频通话/DNS/实时游戏 |

### DNS 解析流程

```
用户输入 www.example.com
        ↓
1. 浏览器缓存 → 检查是否已缓存
        ↓
2. 操作系统缓存 → 检查 hosts 文件及本地 DNS 缓存
        ↓
3. 本地 DNS 服务器 → 配置的 DNS（如 8.8.8.8 / 114.114.114.114）
        ↓
4. 根域名服务器 → 返回顶级域服务器地址
        ↓
5. 顶级域服务器（.com） → 返回权威 DNS 地址
        ↓
6. 权威 DNS 服务器 → 返回最终 IP 地址
        ↓
7. 浏览器与目标 IP 建立 TCP 连接
```

**DNS 记录类型：**

| 记录类型 | 含义 | 示例 |
|---------|------|------|
| A | 域名 → IPv4 | example.com → 93.184.216.34 |
| AAAA | 域名 → IPv6 | example.com → 2606:2800:220:1:248:1893:25c8:1946 |
| CNAME | 别名指向 | www.example.com → example.com |
| MX | 邮件服务器 | mail.example.com |
| NS | DNS 服务器 | ns1.example.com |
| TXT | 文本记录（SPF/DKIM验证） | v=spf1 include:_spf.google.com ~all |

### Cookie vs Session vs Token

| 维度 | Cookie | Session | Token（JWT） |
|------|--------|---------|-------------|
| 存储位置 | 客户端（浏览器） | 服务端（内存/数据库） | 客户端 |
| 安全性 | 低（可被篡改） | 高 | 中（签名验证但需防泄露） |
| 跨域能力 | 默认不可跨域 | 不可跨域（依赖SessionID传递） | 支持跨域 |
| 存储大小 | 4KB | 无限制（服务端） | 不受限 |
| 性能影响 | 每次请求携带 | 服务端查找 | 无状态验证 |
| 适用场景 | 小型状态存储 | 单体应用会话 | 分布式/移动端/API认证 |

**JWT 结构（Header.Payload.Signature）：**
```
eyJhbGciOiJIUzI1NiJ9          ← Header（算法声明）
.eyJ1c2VySWQiOjEyM30         ← Payload（载荷：用户ID等）
.SflKxwRJSMeKKF2QT4fwpMe     ← Signature（签名验证）
```

### Cookie 属性详解

| 属性 | 说明 |
|------|------|
| Domain | 可访问该Cookie的域名 |
| Path | 可访问该Cookie的路径（默认/） |
| Expires/Max-Age | 过期时间 |
| HttpOnly | JavaScript无法访问，防XSS |
| Secure | 仅HTTPS传输 |
| SameSite | 防CSRF（Strict/Lax/None） |

## 动手实操

### 抓包工具配置（Fiddler/Charles）

**Fiddler HTTPS 抓包配置：**

```
1. Tools → Options → HTTPS
2. 勾选 "Decrypt HTTPS traffic"
3. 点击 "Actions" → "Trust Root Certificate"
4. 手机安装证书：浏览器访问 http://[PC_IP]:8888
5. 手机代理设置：手动 → IP为PC地址 → 端口8888
```

**Charles HTTPS 抓包配置：**

```
1. Help → SSL Proxying → Install Charles Root Certificate
2. Proxy → SSL Proxying Settings → 勾选 Enable SSL Proxying
3. 添加 Host: * Port: 443 → OK
4. 手机安装证书：浏览器访问 chls.pro/ssl
5. 手机代理设置同 Fiddler
```

**常用抓包技巧：**

| 操作 | Fiddler | Charles |
|------|---------|---------|
| 过滤域名 | Filters → Use Filters → Hosts | Proxy → Recording Settings → Include |
| 修改请求 | 断点设置：Rules → Automatic Breakpoints → Before Requests | Breakpoint 功能 |
| 重放请求 | 右键 Request → Replay → Reissue | 右键 Repeat |
| 限速模拟 | Rules → Performance → Simulate Modem Speeds | Proxy → Throttle Settings |
| 断言验证 | 使用 Filters 配合 Search 功能 | 使用 Map Local/Map Remote |

### 状态码检查（单接口验证）

```bash
# 查看HTTP状态码
curl -I https://api.example.com/users

# 查看完整请求响应
curl -v -X POST https://api.example.com/login \
  -H "Content-Type: application/json" \
  -d '{"username":"test","password":"123456"}'

# 指定Cookie
curl -b "sessionid=abc123" https://api.example.com/profile
```

## 常见坑

| 错误 | 说明 |
|------|------|
| 混淆401与403 | 401 = 未认证（没登录），403 = 无权限（已登录但没权限） |
| 抓不到HTTPS包 | 仅安装证书未开启 SSL Proxying 功能 |
| 认为304=成功 | 304 是缓存命中，实际没有传输内容 |
| 忽略SameSite策略 | Chrome 默认 SameSite=Lax 导致部分Cookie不发送 |
| 服务端Session丢失 | 分布式环境下Session未做共享，应使用Redis集中存储 |
| JWT过期未处理 | 前/后端均需处理Token过期逻辑，避免静默失效 |
