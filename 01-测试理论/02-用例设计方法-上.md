# 02-用例设计方法-上

> 课时：90 min | 难度：★★★

## 学习目标

- 掌握等价类划分的原理与步骤，能对一个输入域划分有效等价类和无效等价类
- 掌握边界值分析的三点法（内点、上点、离点），能针对数值型输入设计边界测试用例
- 掌握判定表方法，能对多条件组合场景进行全量覆盖设计
- 对同一验证场景能比较三种方法的适用性与测试覆盖差异

## 核心概念

### 等价类划分（Equivalence Partitioning）

**定义**：将输入域划分为若干子集，使同一子集中任意输入值在程序中的行为等价，只需从每个子集中选取一个代表值作为测试用例。

**分类**：

| 类别 | 说明 | 是否必须 |
|------|------|----------|
| 有效等价类 | 符合需求规格、有意义的输入集合 | 是（至少1个用例） |
| 无效等价类 | 不符合需求规格、无意义或非法的输入集合 | 是（每个无效类至少1个用例） |

**设计步骤**：

1. 确定输入数据类型（数值、字符串、布尔、枚举等）
2. 划分有效等价类
3. 划分无效等价类（注意：每个无效类独立测试，不合并）
4. 为每个等价类编号
5. 设计用例覆盖尽可能多的未覆盖有效类；每个无效类单独一条用例

**示例：用户名输入验证**

需求：用户名由字母、数字、下划线组成，长度6-20字符，必须以字母开头。

| 编号 | 等价类描述 | 类别 |
|------|-----------|------|
| EC1 | 长度6-20，字母开头，含字母/数字/下划线 | 有效 |
| EC2 | 长度<6 | 无效 |
| EC3 | 长度>20 | 无效 |
| EC4 | 以数字开头 | 无效 |
| EC5 | 以下划线开头 | 无效 |
| EC6 | 包含特殊字符（如!@#） | 无效 |
| EC7 | 空字符串 | 无效 |
| EC8 | 纯空格 | 无效 |

对应测试用例：

| 用例ID | 输入 | 覆盖等价类 | 预期结果 |
|--------|------|-----------|----------|
| TC01 | `Alice_01` | EC1 | 验证通过 |
| TC02 | `Bob` | EC2 | 提示"长度不足6位" |
| TC03 | `A1234567890123456789X` | EC3 | 提示"长度超过20位" |
| TC04 | `1Alice` | EC4 | 提示"必须以字母开头" |
| TC05 | `_Alice` | EC5 | 提示"必须以字母开头" |
| TC06 | `Ali!ce` | EC6 | 提示"仅允许字母、数字、下划线" |
| TC07 | （空） | EC7 | 提示"不能为空" |
| TC08 | `      ` | EC8 | 提示"不能为空或仅包含空格" |

### 边界值分析（Boundary Value Analysis）

**定义**：基于"错误往往发生在边界而非中间"的经验，针对输入域的边界及边界附近的值设计测试用例。

**三点法**：

```
|------------------[ 输入域 ]------------------|
      ↑         ↑              ↑         ↑
    离点-1     上点           上点      离点+1
              (边界)        (边界)
```

| 点类型 | 说明 | 位置 |
|--------|------|------|
| 内点（On Point） | 输入域内部的任意有效值 | 区间内部 |
| 上点（Boundary Point） | 边界上的值（最大/最小有效值） | 边界 |
| 离点（Off Point） | 刚好超出边界的无效值 | 边界±1 |

**对于闭区间 [a, b]**：内点取 (a+b)/2 附近；上点取 a 和 b；离点取 a-1 和 b+1。

**示例：年龄字段（允许18-60岁）**

| 用例ID | 输入值 | 点类型 | 预期结果 |
|--------|--------|--------|----------|
| TC01 | 17 | 离点 | 拒绝：年龄不足 |
| TC02 | 18 | 上点（最小值） | 接受 |
| TC03 | 30 | 内点 | 接受 |
| TC04 | 60 | 上点（最大值） | 接受 |
| TC05 | 61 | 离点 | 拒绝：年龄超限 |

**与等价类划分的关系**：边界值分析是等价类划分的补充，通常将两者结合使用——先划分等价类，再对每个等价类做边界值分析。

### 判定表（Decision Table）

**定义**：以表格形式列出所有条件组合及对应的动作，确保条件组合的全集覆盖，适用于多条件逻辑判断场景。

**结构**：

```
            条件桩          动作桩
            ┌───┬───┬───┐  ┌───┐
            │ C1│ C2│ C3│  │ A1│
            ├───┼───┼───┤  ├───┤
规则1       │ T │ T │ T │  │ √ │
规则2       │ T │ T │ F │  │ √ │
...         │...│...│...│  │...│
规则N       │ F │ F │ F │  │   │
            └───┴───┴───┘  └───┘
```

若有 N 个布尔条件，则最多有 2^N 条规则。

**4个组成部分**：

| 组成部分 | 说明 |
|----------|------|
| 条件桩（Condition Stub） | 列出所有输入条件 |
| 条件项（Condition Entry） | 每条规则中各条件的取值（T/F/-） |
| 动作桩（Action Stub） | 列出所有可能的动作 |
| 动作项（Action Entry） | 对应规则下执行的动作 |

**示例：订单折扣判定**

条件：会员等级（普通/VIP）、订单金额（<500/≥500）、是否使用优惠券（是/否）
动作：给予折扣（无折扣/9折/8折/7折）

| 规则 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|------|---|---|---|---|---|---|---|---|
| **会员VIP** | T | T | T | T | F | F | F | F |
| **金额≥500** | T | T | F | F | T | T | F | F |
| **使用优惠券** | T | F | T | F | T | F | T | F |
| **折扣7折** | √ | | | | | | | |
| **折扣8折** | | √ | | | √ | | | |
| **折扣9折** | | | √ | √ | | | √ | |
| **无折扣** | | | | | | √ | | √ |

**简化后（合并相同动作的规则）**：

| 条件/规则 | R1 | R2 | R3 | R4 |
|-----------|----|----|----|----|
| 会员VIP | T | T | - | F |
| 金额≥500 | T | - | - | - |
| 使用优惠券 | T | F | - | - |
| 折扣7折 | √ | | | |
| 折扣8折 | | √ | √ | |
| 无折扣 | | | | √ |

合并规则：VIP+金额≥500 → 8折（无需关注优惠券）；VIP+使用优惠券+金额<500 → 8折；非VIP或金额<500且无优惠券 → 无折扣。

## 动手实操

### 任务1：对用户注册表单设计等价类+边界值测试用例

需求：注册表单中"手机号"字段要求为11位数字，以1开头。

1. 分析需求维度

```
维度1：是否为11位数字
维度2：是否以1开头
维度3：是否全为数字
```

2. 划分等价类

| 编号 | 等价类 | 类别 |
|------|--------|------|
| EC1 | 11位数字，1开头 | 有效 |
| EC2 | 非11位（<11或>11） | 无效 |
| EC3 | 非1开头 | 无效 |
| EC4 | 含非数字字符 | 无效 |

3. 边界值分析（针对长度）

| 边界 | 值示例 | 预期 |
|------|--------|------|
| 上点-1长度 | `1380013800`（10位） | 拒绝 |
| 上点（最低有效） | `13800138000`（11位） | 接受 |
| 上点（最高有效） | `19999999999`（11位） | 接受 |
| 离点+1 | `138001380000`（12位） | 拒绝 |

4. 编写Python脚本生成测试数据

```python
def generate_phone_test_cases():
    cases = [
        {"input": "13800138000", "expected": "accept",     "reason": "有效：11位1开头"},
        {"input": "1380013800",  "expected": "reject",     "reason": "无效：10位"},
        {"input": "138001380000","expected": "reject",     "reason": "无效：12位"},
        {"input": "23800138000", "expected": "reject",     "reason": "无效：非1开头"},
        {"input": "1380013800a", "expected": "reject",     "reason": "无效：含字母"},
        {"input": "138-0013-8000","expected": "reject",    "reason": "无效：含横杠"},
        {"input": "",            "expected": "reject",     "reason": "无效：空"},
    ]
    for i, tc in enumerate(cases, 1):
        flag = "PASS" if validate_phone(tc["input"]) == (tc["expected"] == "accept") else "FAIL"
        print(f"TC{i:02d}: {tc['input']:<18} → {flag} [{tc['reason']}]")

def validate_phone(phone: str) -> bool:
    return len(phone) == 11 and phone.isdigit() and phone[0] == '1'

if __name__ == "__main__":
    generate_phone_test_cases()
```

5. 运行脚本验证

```bash
python test_phone_validation.py
```

预期输出（若被测函数正确）：

```
TC01: 13800138000        → PASS [有效：11位1开头]
TC02: 1380013800         → PASS [无效：10位]
TC03: 138001380000       → PASS [无效：12位]
TC04: 23800138000        → PASS [无效：非1开头]
TC05: 1380013800a        → PASS [无效：含字母]
TC06: 138-0013-8000      → PASS [无效：含横杠]
TC07:                     → PASS [无效：空]
```

### 任务2：构建判定表处理登录失败锁定策略

需求：连续登录失败3次，账户锁定30分钟。需覆盖条件：
- 是否已锁定
- 是否达到失败次数
- 锁定时间是否已过

```python
def login_decision(is_locked: bool, fail_count: int, lock_expired: bool) -> str:
    """
    判定表实现：登录锁定策略
    """
    if is_locked and not lock_expired:
        return "拒绝：账户已锁定"
    if fail_count >= 3:
        if not is_locked:
            return "拒绝：超过失败次数，已锁定"
        elif lock_expired:
            return "允许：锁定已过期，请重试"
    return "允许：登录流程继续"

# 决策表测试数据
decision_table = [
    # (is_locked, fail_count, lock_expired, expected_action)
    (True,  0, False, "拒绝：账户已锁定"),
    (True,  3, True,  "允许：锁定已过期，请重试"),
    (False, 3, False, "拒绝：超过失败次数，已锁定"),
    (False, 2, False, "允许：登录流程继续"),
]

for locked, fails, expired, expected in decision_table:
    result = login_decision(locked, fails, expired)
    status = "PASS" if result == expected else "FAIL"
    print(f"Locked={locked}, Fails={fails}, Expired={expired} → {status}")
```

## 常见坑

1. **等价类合并多个无效类** — 无效类必须独立测试，一条用例只覆盖一个无效类，否则无法精确定位缺陷原因。
2. **边界值只测上点不测离点** — 离点（刚好无效的值）是开发者最容易遗漏的判断分支，必须测试。
3. **判定表规则有遗漏** — N个条件应有2^N条规则，需逐条列出，避免凭经验"想当然"跳过大段组合。
4. **条件项与动作项混淆** — 条件桩是输入条件（如"会员=VIP"），动作桩是输出动作（如"折扣=8折"），不可混用。
5. **等价类中忽略空值/null** — 空输入、null值是常见边界情况，必须单独划分为无效类。
6. **判定表中条件存在依赖关系时强行全排列** — 若条件间存在互斥或依赖，应合并规则或添加约束列，不应产生无效规则。
