## 核心概念

### 1. LLM用于测试用例生成的原理

大语言模型通过学习海量代码与文档，掌握了软件测试的基本模式。生成测试用例时，模型接收被测对象描述（接口文档、需求文本、代码片段），输出覆盖各类场景的测试输入与预期结果。

关键能力：
- 从自然语言描述中提取功能边界
- 按测试设计方法（边界值、等价类、场景法）组合输入
- 生成结构化输出（表格、JSON、Markdown）
- 补充人类容易遗漏的异常路径

### 2. 提示词工程核心技巧

**角色设定（Role Prompting）**
指定模型扮演资深测试工程师，使其输出更专业、更贴近实际工程实践。

**任务分解（Chain of Thought）**
要求模型先分析需求，再选择测试设计方法，最后生成用例。分步推理显著提升输出质量。

**输出格式约束（Format Constraint）**
明确指定输出格式，如Markdown表格、CSV、JSON，确保结果可直接导入测试管理系统。

**范例注入（Few-shot Example）**
提供1-2个高质量示例，让模型理解期望的输出结构与深度。

### 3. 边界值与等价类的AI生成

传统边界值分析：输入域为[a,b]时，取a、a+1、b-1、b及a-1、b+1。
AI增强边界值：结合业务规则自动识别隐式边界（如年龄上限150、密码长度限制）。

等价类划分：有效等价类 + 无效等价类。AI可一次性枚举所有等价类组合，避免遗漏。

### 4. 场景法测试用例生成

场景法描述用户操作流程。AI擅长将用例场景扩展为多分支路径：
- 基本流（Happy Path）
- 备选流（Alternative Flow）
- 异常流（Exception Flow）

### 5. AI生成用例的局限性

- **幻觉问题**：可能生成不存在的接口参数或错误的状态码
- **理解偏差**：对业务上下文理解不足，生成脱离实际的预期结果
- **覆盖盲区**：无法自动追踪代码覆盖率，可能遗漏分支
- **幻觉性自信**：输出格式规范但内容可能有误，需人工验证

## 动手实操

### 实操1：生成登录功能的测试用例

使用以下提示词：

```
你是一名资深软件测试工程师。请为以下登录功能生成测试用例。

功能描述：
- 用户名：6-20位字母数字
- 密码：8-16位，必须包含大小写字母和数字
- 登录失败3次锁定账户15分钟
- 支持短信验证码备用登录

要求：
1. 使用边界值分析和等价类划分
2. 输出格式为Markdown表格，列：用例编号、标题、前置条件、输入数据、预期结果、优先级
3. 覆盖正常流、异常流、安全场景
```

### 实操3：使用ChatGPT API批量生成

```python
import openai
import pandas as pd

def generate_test_cases(api_spec: str, method: str) -> str:
    prompt = f"""
    为以下API生成{method}方法的测试用例。
    输出Markdown表格，包含：用例ID、描述、输入、预期结果、测试类型
    
    API描述：{api_spec}
    """
    response = openai.ChatCompletion.create(
        model="gpt-4",
        messages=[
            {"role": "system", "content": "你是资深测试工程师，精通测试设计方法。"},
            {"role": "user", "content": prompt}
        ],
        temperature=0.3
    )
    return response.choices[0].message.content

spec = "用户注册接口：用户名3-20字符，邮箱格式校验，密码强度验证"
result = generate_test_cases(spec, "边界值分析")
print(result)
```

## 常见坑

1. **提示词过于笼统**："帮我写测试用例"：输出质量极差。必须提供具体的被测对象描述、格式要求、覆盖范围
2. **忽略输出验证**：直接信任AI输出，未对生成的用例进行人工核对，导致用例本身有误
3. **未指定角色**：模型默认按通用助手回答，输出缺乏测试专业性
4. **过度依赖AI**：放弃测试设计思考，完全依赖生成结果，丧失测试独立性
5. **上下文过长**：一次性粘贴整个需求文档，超出上下文窗口，模型丢失关键信息
6. **缺乏迭代**：期望一次生成完美结果，未采用"生成→评审→修改提示词→再生成"的迭代流程
