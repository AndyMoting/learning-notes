# 评分标准速查

> GZ034 软件测试赛项 · 五大任务评分要点与应试策略

---

| 任务 | 内容 | 分值 | 占比 | 建议用时 |

## 二、各任务评分细则

### 任务一：测试计划制定（100分）

| 评分项 | 分值 | 评分要点 |
|--------|------|----------|
| 测试目标 | 15分 | 目标明确、可衡量、覆盖核心功能 |
| 测试范围 | 20分 | 包含/不包含模块界定清晰 |
| 测试策略 | 25分 | 方法选择合理、层次分明 |
| 资源安排 | 15分 | 人员分工明确、工具环境完整 |
| 进度安排 | 15分 | 时间节点合理、可执行 |
| 风险评估 | 10分 | 风险识别全面、应对措施有效 |

### 任务二：测试用例设计（100分）

| 评分项 | 分值 | 评分要点 |
|--------|------|----------|
| 用例规范性 | 20分 | 编号规则统一、字段完整 |
| 覆盖度 | 30分 | 等价类、边界值、场景法均有覆盖 |
| 有效性 | 25分 | 步骤可执行、预期结果明确 |
| 优先级划分 | 15分 | 优先级与业务重要性匹配 |
| 用例数量 | 10分 | 数量达标（通常要求≥30条） |

### 任务三：Bug报告撰写（100分）

| 评分项 | 分值 | 评分要点 |
|--------|------|----------|
| Bug标题 | 10分 | 简明准确描述问题 |
| 复现步骤 | 25分 | 步骤清晰、可复现 |
| 预期/实际结果 | 20分 | 对比明确、描述准确 |
| 严重程度判定 | 20分 | 等级判定正确 |
| 附件完整性 | 15分 | 截图/日志齐全 |
| 环境信息 | 10分 | 环境描述完整 |

### 任务四：自动化测试（100分）

| 评分项 | 分值 | 评分要点 |
|--------|------|----------|
| 脚本可运行性 | 30分 | 脚本可直接执行、无语法错误 |
| 元素定位 | 20分 | 定位方式稳定、可维护 |
| 断言设计 | 20分 | 断言覆盖关键验证点 |
| 代码规范 | 15分 | 命名规范、结构清晰 |
| 异常处理 | 15分 | 异常捕获与日志记录 |

### 任务五：性能测试（100分）

| 评分项 | 分值 | 评分要点 |
|--------|------|----------|
| 脚本设计 | 25分 | 场景设计合理、参数化正确 |
| 场景执行 | 25分 | 并发设置正确、执行无报错 |
| 结果分析 | 30分 | TPS/响应时间/错误率分析准确 |
| 报告撰写 | 20分 | 结论明确、有数据支撑 |

## 三、常见扣分点汇总

### 通用扣分

| 扣分项 | 扣分幅度 | 说明 |
|--------|----------|------|
| 格式不规范 | -5~10分 | 模板字段缺失、编号混乱 |
| 命名不规范 | -3~5分 | 中英文混用、无意义命名 |
| 截图不完整 | -5~10分 | 缺少关键步骤截图 |
| 超时未完成 | 按未完成比例扣分 | 每超10分钟扣5分 |

### 任务一常见扣分

| 扣分项 | 扣分幅度 | 说明 |
|--------|----------|------|
| 测试范围遗漏 | -10~15分 | 核心模块未纳入 |
| 策略与实际脱节 | -10分 | 写了方法但用例中未体现 |
| 进度不可行 | -5~10分 | 时间分配与任务量不匹配 |

### 任务二常见扣分

| 扣分项 | 扣分幅度 | 说明 |
|--------|----------|------|
| 覆盖度不足 | -15~25分 | 仅覆盖正常流程，缺少异常/边界 |
| 预期结果模糊 | -10分 | 使用"正确显示"等笼统描述 |
| 步骤不可执行 | -10分 | 缺少具体输入值 |

### 任务三常见扣分

| 扣分项 | 扣分幅度 | 说明 |
|--------|----------|------|
| 步骤不可复现 | -15~20分 | 步骤跳跃、缺少关键操作 |
| 严重程度误判 | -10分 | 致命/严重混淆 |
| 缺少附件 | -10分 | 无截图或截图不清晰 |

### 任务四常见扣分

| 扣分项 | 扣分幅度 | 说明 |
|--------|----------|------|
| 脚本无法运行 | -20~30分 | 语法错误、依赖缺失 |
| 硬编码定位 | -10分 | 使用绝对XPath |
| 无断言 | -15分 | 脚本执行但无验证逻辑 |

### 任务五常见扣分

| 扣分项 | 扣分幅度 | 说明 |
|--------|----------|------|
| 参数化错误 | -10~15分 | 未使用CSV/变量 |
| 监听器缺失 | -10分 | 缺少聚合报告/结果树 |
| 结论无数据 | -15分 | 结论与指标数据不一致 |

## 四、时间分配策略

### 推荐时间分配（总计210分钟）

| 阶段 | 任务 | 时间 | 说明 |
|------|------|------|------|
| 第一阶段 | 任务一 + 任务二 | 90分钟 | 先计划后用例，逻辑连贯 |
| 第二阶段 | 任务三 | 40分钟 | Bug报告依赖前两步执行结果 |
| 第三阶段 | 任务四 | 45分钟 | 自动化脚本编写与调试 |
| 第四阶段 | 任务五 | 35分钟 | 性能测试执行与报告 |
| 缓冲 | 检查与提交 | 10分钟 | 格式检查、文件命名 |

### 时间紧张时的取舍顺序

1. **优先完成**：任务二（25%权重，产出明确）
2. **其次完成**：任务四（20%权重，脚本可运行即得分）
3. **再次完成**：任务一 + 任务三（各20%权重）
4. **最后处理**：任务五（15%权重，场景相对固定）

## 五、优先级策略

### 高分值优先原则

按"分值密度"排序（每分钟可得分值）：

| 任务 | 分值 | 建议用时 | 分值密度 | 优先级 |
|------|------|----------|----------|--------|
| 任务二 | 100分 | 50分钟 | 2.0分/分钟 | 最高 |
| 任务四 | 100分 | 45分钟 | 2.2分/分钟 | 最高 |
| 任务三 | 100分 | 40分钟 | 2.5分/分钟 | 高 |
| 任务一 | 100分 | 40分钟 | 2.5分/分钟 | 高 |
| 任务五 | 100分 | 35分钟 | 2.9分/分钟 | 中 |

### 保底得分策略

| 目标分数 | 策略 |
|----------|------|
| 60分（及格） | 任务一拿60% + 任务二拿60% + 任务三拿60% |
| 70分（良好） | 任务一拿70% + 任务二拿70% + 任务四拿60% |
| 80分（优秀） | 任务二拿85% + 任务四拿80% + 任务三拿75% |
| 90分（顶尖） | 全部任务稳定85%以上 |

### 答题顺序建议

```
1. 通读全部任务要求（5分钟）
2. 任务一：测试计划（40分钟）
3. 任务二：用例设计（50分钟）
4. 任务三：Bug报告（40分钟）
5. 任务四：自动化测试（45分钟）
6. 任务五：性能测试（35分钟）
7. 检查提交（10分钟）
```
