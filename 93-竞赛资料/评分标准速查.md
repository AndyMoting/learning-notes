# 评分标准速查

> GZ034 软件测试赛项 · 100 分制任务拆解、扣分点与时间策略

## 一、赛项结构与分值权重

| 模块 | 分值 | 占比 | 建议用时 | 核心交付物 |
|------|------|------|----------|------------|
| 功能测试 | 45 | 45% | 70 min | 测试计划、测试用例、Bug 报告、测试报告 |
| 自动化测试 | 15 | 15% | 35 min | Selenium 脚本、unittest、ddt、PO 框架 |
| 性能测试 | 15 | 15% | 30 min | JMeter/LoadRunner 脚本、场景、结果截图与分析 |
| 单元测试 | 10 | 10% | 15 min | JUnit 测试类、覆盖数据、运行结果 |
| API 测试 | 10 | 10% | 15 min | Postman Collection、数据驱动、Token 关联、断言 |
| 职业素养 | 5 | 5% | 贯穿全程 | 命名、截图、目录、团队协作、展示表达 |
| **合计** | **100** | **100%** | **180 min** |  |

如果当年官方规程与本表不同，以官方规程为准。

## 二、各模块评分细则

### 功能测试（45 分）

| 子项 | 分值 | 评分要点 |
|------|------|----------|
| 测试计划 | 8 | 测试目标明确；范围边界清晰；策略、资源、进度、风险完整 |
| 测试用例 | 15 | 字段完整；覆盖核心流程、异常、边界；步骤可执行；预期结果明确 |
| Bug 报告 | 12 | 标题准确；复现步骤清晰；预期/实际对比明确；严重程度合理；截图完整 |
| 测试报告 | 10 | 执行统计、缺陷统计、测试结论、风险建议完整 |

### 自动化测试（15 分）

| 子项 | 分值 | 评分要点 |
|------|------|----------|
| 基础脚本 | 3 | 浏览器启动、定位、输入、点击、截图可运行 |
| unittest 结构 | 3 | setUp/tearDown/test 方法、断言完整 |
| ddt 数据驱动 | 4 | 数据读取、参数拆包、断言、失败截图 |
| Page Object 框架 | 4 | BasePage、页面类、测试类、运行入口分层清晰 |
| 运行结果 | 1 | 有运行证据、报告或截图 |

### 性能测试（15 分）

| 子项 | 分值 | 评分要点 |
|------|------|----------|
| 脚本设计 | 3 | 请求正确，能录制/编写并回放 |
| 事务/断言/检查点 | 3 | 关键业务链路有事务统计和成功判断 |
| 参数化/关联 | 3 | 数据不写死，动态值能提取和复用 |
| 场景设计 | 3 | 线程数、Ramp-Up、循环、集合点设置合理 |
| 结果分析 | 3 | 响应时间、吞吐量、错误率、瓶颈结论完整 |

### 单元测试（10 分）

| 子项 | 分值 | 评分要点 |
|------|------|----------|
| 代码分析 | 2 | 能识别输入、分支、边界和覆盖目标 |
| 测试数据设计 | 3 | 数据能覆盖关键语句/分支 |
| JUnit 测试类 | 3 | 注解、测试方法、断言可运行 |
| 覆盖率达标 | 2 | 覆盖率满足题目要求 |

### API 测试（10 分）

| 子项 | 分值 | 评分要点 |
|------|------|----------|
| 请求构建 | 3 | URL、方法、Header、Body 正确 |
| 数据驱动 | 3 | Runner 能按多组数据执行 |
| Token 关联 | 2 | 登录后自动保存并传递 Token |
| 结果断言 | 2 | 状态码、业务字段、错误信息断言完整 |

### 职业素养（5 分）

| 子项 | 分值 | 评分要点 |
|------|------|----------|
| 文件命名 | 1 | 命名符合题目要求，大小写和编号正确 |
| 目录结构 | 1 | 文件放在指定目录，无遗漏 |
| 截图规范 | 1 | 截图清晰、命名统一、能证明结果 |
| 团队协作 | 1 | 分工明确、进度同步、支援及时 |
| 展示表达 | 1 | 汇报结构清晰，时间可控 |

## 三、常见扣分点汇总

### 通用扣分

| 扣分项 | 常见扣分 | 说明 |
|--------|----------|------|
| 文件命名不符合要求 | 1-5 分 | 文件名、路径、大小写、编号错误 |
| 截图不完整 | 1-5 分 | 缺少关键步骤、结果或参数截图 |
| 输出格式不规范 | 1-5 分 | 模板字段缺失、排版混乱、编号不统一 |
| 脚本无法运行 | 视模块严重程度扣分 | 语法错误、依赖缺失、路径写死 |
| 未按时提交 | 按未完成比例扣分 | 最后检查时间不足导致遗漏 |

### 功能测试常见扣分

| 扣分项 | 说明 |
|--------|------|
| 测试范围遗漏 | 核心模块未纳入计划 |
| 用例只覆盖正常流程 | 缺少异常、边界、权限、状态变化 |
| 预期结果模糊 | 使用“正确显示”“正常提示”等笼统描述 |
| Bug 步骤不可复现 | 缺少前置条件、测试数据或关键操作 |
| 测试报告无结论 | 只有数据，没有上线风险判断 |

### 自动化测试常见扣分

| 扣分项 | 说明 |
|--------|------|
| 绝对 XPath | 页面结构变化即失效，维护性差 |
| 固定 sleep 过多 | 脚本不稳定，容易偶发失败 |
| 无断言 | 只执行操作，不验证结果 |
| 数据驱动路径写死 | 换电脑后 CSV 或截图路径失效 |
| PO 分层混乱 | 定位器、业务操作、测试断言混在一起 |

### 性能测试常见扣分

| 扣分项 | 说明 |
|--------|------|
| 没有断言 | 失败请求也被统计为成功 |
| 参数化无效 | 所有虚拟用户使用同一数据 |
| 只跑脚本不分析 | 没有响应时间、吞吐量、错误率结论 |
| 截图缺失 | 缺少线程组、请求、断言、报告证据 |

### 单元/API 常见扣分

| 扣分项 | 说明 |
|--------|------|
| 覆盖数据不足 | 漏掉关键分支或边界 |
| 断言不精确 | 只断言非空，不断言具体结果 |
| Token 手动复制 | 没有体现自动关联 |
| Runner 结果未保存 | 无法证明数据驱动执行情况 |

## 四、180 分钟时间分配策略

| 阶段 | 时间 | 内容 | 说明 |
|------|------|------|------|
| 0-10 min | 审题与分工 | 通读题目、确认环境、分配角色 | 不急着写代码 |
| 10-80 min | 功能测试 | 计划 15 + 用例 25 + Bug 20 + 报告 10 | 最高分模块，必须保证完整 |
| 80-115 min | 自动化测试 | 4 道脚本题 | 先拿基础题，再做 PO |
| 115-145 min | 性能测试 | 脚本、场景、截图、分析 | 跑通后立刻写结论 |
| 145-160 min | 单元测试 | JUnit 题 | 先覆盖主路径和边界 |
| 160-175 min | API 测试 | Postman 数据驱动、Token、断言 | 截图证明请求和结果 |
| 175-180 min | 检查提交 | 文件名、路径、截图、报告 | 不再新增内容 |

## 五、取舍策略

| 情况 | 处理 |
|------|------|
| 功能测试 80 分钟仍未完成 | 先补测试报告结论和 Bug 汇总，不继续扩写用例 |
| 自动化某题卡住 8 分钟 | 先跳过，保留框架，做下一题 |
| 性能脚本跑不通 | 保留配置截图，写清场景设计和预期分析 |
| 单元测试覆盖率不足 | 优先补关键分支数据，不追求大量重复用例 |
| API Token 关联失败 | 先完成无鉴权题，再回头排查变量名和 Tests 脚本 |
| 剩余 5 分钟 | 只检查提交物，不再重构或大改 |

## 六、赛前检查清单

### 工具准备

- [ ] Postman 已安装并能运行 Runner
- [ ] Selenium + 浏览器驱动已配置
- [ ] JMeter 已安装并能生成报告
- [ ] LoadRunner 如赛项要求则完成录制/回放验证
- [ ] JDK、Eclipse、JUnit 可运行最小测试
- [ ] 截图工具可用，保存路径已确认

### 模板准备

- [ ] 测试计划表头能默写
- [ ] 测试用例表头能默写
- [ ] Bug 报告字段能默写
- [ ] 测试报告结构能默写
- [ ] Selenium + unittest + ddt 基础结构能默写
- [ ] JMeter 线程组、请求、断言、参数化、报告路径能独立配置

### 心态准备

- [ ] 明确自己主任务和支援任务
- [ ] 明确每个时间节点该完成什么
- [ ] 明确卡住超过 8-10 分钟就跳过
- [ ] 明确最后 5 分钟只检查提交物
