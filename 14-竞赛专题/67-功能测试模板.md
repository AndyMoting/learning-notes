# 67-功能测试模板
> 课时：45 min | 难度：★★★

## 学习目标
- 掌握测试计划、用例、Bug 报告、测试报告四份文档的标准模板
- 学会快速填充模板关键字段，节省现场编写时间
- 理解文档格式规范对专业质量分的影响

## 核心概念

### 测试计划模板（6 要素）

| 序号 | 要素 | 内容说明 |
|------|------|---------|
| 1 | 测试目标 | 验证 XX 系统 XX 功能是否满足需求规格说明书 |
| 2 | 测试范围 | 列出本次测试覆盖的模块与排除项 |
| 3 | 测试策略 | 黑盒测试（等价类、边界值、场景法、错误推测） |
| 4 | 测试资源 | 人员分工、测试环境（硬件/软件/网络） |
| 5 | 测试进度 | 各阶段时间节点（计划→用例→执行→报告） |
| 6 | 风险风险 | 环境异常、需求变更、人员缺勤及应对措施 |

### 测试用例模板（10 字段）

| 字段 | 说明 |
|------|------|
| 用例编号 | 项目缩写-模块-序号（如 EC-LOGIN-001） |
| 用例标题 | 简明描述测试目的 |
| 所属模块 | 功能模块名称 |
| 前置条件 | 执行用例前系统应处的状态 |
| 测试步骤 | 编号列表，每步一个操作 |
| 测试数据 | 输入值、文件名、账号等 |
| 预期结果 | 每步对应的可验证输出 |
| 实际结果 | 执行后填写（初始为空） |
| 优先级 | P0（核心）/ P1（重要）/ P2（次要） |
| 执行结果 | Pass / Fail / Blocked |

**示例：**

| 用例编号 | EC-LOGIN-001 |
|---------|-------------|
| 用例标题 | 用户名密码正确登录验证 |
| 所属模块 | 登录模块 |
| 前置条件 | 已注册用户 testuser / 123456 |
| 测试步骤 | 1. 打开登录页 2. 输入用户名 testuser 3. 输入密码 123456 4. 点击登录按钮 |
| 测试数据 | 用户名: testuser, 密码: 123456 |
| 预期结果 | 1. 页面加载正常 2-3. 输入框显示输入内容 4. 跳转至首页，显示欢迎信息 |
| 优先级 | P0 |

### Bug 报告模板（6 要素）

| 字段 | 说明 |
|------|------|
| Bug 编号 | BUG-模块-序号（如 BUG-LOGIN-001） |
| 标题 | 【模块】简短描述缺陷现象 |
| 严重等级 | Critical / Major / Minor / Trivial |
| 复现步骤 | 编号列表，含测试数据 |
| 实际结果 | 系统实际表现 |
| 预期结果 | 需求规定的正确表现 |

**示例：**

| Bug 编号 | BUG-LOGIN-003 |
|---------|--------------|
| 标题 | 【登录】输入错误密码 5 次后账户未锁定 |
| 严重等级 | Major |
| 复现步骤 | 1. 打开登录页 2. 输入用户名 testuser 3. 输入错误密码 wrong 4. 重复步骤 2-3 共 5 次 |
| 实际结果 | 第 5 次错误后仍可继续输入密码，账户未锁定 |
| 预期结果 | 第 5 次错误后账户锁定 30 分钟，提示"账户已锁定" |

### 测试报告模板

```
1. 测试概述
   1.1 测试目标
   1.2 测试范围
   1.3 测试时间
2. 测试环境
   2.1 硬件环境
   2.2 软件环境
3. 测试执行情况
   3.1 用例执行统计（总数/已执行/未执行）
   3.2 通过率
4. 缺陷统计
   4.1 缺陷等级分布（Critical/Major/Minor/Trivial）
   4.2 缺陷模块分布
   4.3 缺陷趋势图
5. 测试结论
   5.1 功能是否达标
   5.2 遗留问题
6. 建议
   6.1 修复优先级
   6.2 回归测试建议
```

### 文档格式规范

| 项目 | 标准 |
|------|------|
| 字体 | 中文宋体/英文 Times New Roman |
| 字号 | 标题 14pt 加粗 / 正文 12pt |
| 行距 | 1.5 倍行距 |
| 命名 | 任务号-文档类型-日期（如 T1-测试计划-20250601） |
| 页眉页脚 | 页眉：文档标题 / 页脚：页码 |

## 动手实操

1. 将上述四份模板保存为 .docx 文件，命名加前缀"TMPL-"
2. 使用样题完成一次完整文档编写，计时 70 分钟
3. 对照评分表自评，记录扣分点
4. 优化模板，将固定内容（如测试策略描述）预填

## 常见坑
- 用例编号不统一——赛前确定编号规则并全程执行
- 预期结果不可验证——每步预期结果必须是可观察的界面变化或数据变化
- Bug 标题模糊——使用"【模块】+ 现象"格式
- 测试报告缺少缺陷统计——至少包含等级分布与模块分布
- 字体混用——全文档统一字体，避免系统自动替换
