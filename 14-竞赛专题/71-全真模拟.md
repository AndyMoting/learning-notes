# 71-全真模拟
> 课时：60 min | 难度：★★★★★

## 学习目标
- 完成 3 小时全真模拟，体验完整竞赛节奏
- 掌握赛后复盘方法与评分对照技巧
- 学会 10 分钟综合展示 PPT 结构与答辩准备

## 核心概念

### 模拟竞赛规则

**时间：** 180 分钟（3 小时）
**环境：** 与正式竞赛一致的软件版本与硬件配置
**题目：** 使用官方样题或往届真题
**纪律：** 禁止查阅资料、禁止使用 AI 工具、禁止交流

**计时节点：**

| 时间点 | 应完成内容 |
|--------|-----------|
| 0:10 | 审题完毕、分工确认 |
| 1:20 | 任务一完成（功能测试四份文档） |
| 1:55 | 任务二完成（自动化 4 题） |
| 2:25 | 任务三完成（性能测试） |
| 2:40 | 任务四完成（单元测试） |
| 2:55 | 任务五完成（API 测试） |
| 3:00 | 检查收尾、提交 |

### 赛后复盘方法

**评分对照：**
1. 下载官方评分表，逐项自评
2. 记录每项扣分原因
3. 计算各任务得分率
4. 识别薄弱环节

**复盘模板：**

| 任务 | 满分 | 得分 | 扣分原因 | 改进措施 |
|------|------|------|---------|---------|
| 任务一 | 45 | | | |
| 任务二 | 15 | | | |
| 任务三 | 15 | | | |
| 任务四 | 10 | | | |
| 任务五 | 10 | | | |
| 职业素养 | 5 | | | |
| **合计** | **100** | | | |

**改进优先级：**
1. 得分率低于 50% 的任务——重点突破
2. 反复出现的扣分点——专项训练
3. 时间超支的任务——优化流程

### 10 分钟综合展示

**PPT 结构（5-8 页）：**

| 页码 | 内容 | 时间 |
|------|------|------|
| 1 | 封面：赛项名称、团队名称、日期 | 30s |
| 2 | 任务概述：五大任务与分工 | 1 min |
| 3 | 功能测试：用例设计思路与覆盖度 | 2 min |
| 4 | 自动化测试：PO 框架设计亮点 | 2 min |
| 5 | 性能测试：场景设计与结果分析 | 2 min |
| 6 | 缺陷分析：典型 Bug 与修复建议 | 1.5 min |
| 7 | 总结：得分点与改进方向 | 1 min |
| 8 | 致谢 | 30s |

**展示要点：**
- 每页不超过 5 个要点
- 使用图表替代文字（缺陷分布饼图、响应时间折线图）
- 重点突出设计思路而非操作步骤
- 控制语速，预留 1 分钟缓冲

### 答辩准备

**常见评委问题：**

| 问题 | 回答要点 |
|------|---------|
| 测试用例如何保证覆盖度？ | 等价类+边界值+场景法组合，覆盖所有输入组合 |
| 自动化框架为什么选择 PO？ | 定位器与业务逻辑分离，维护成本低 |
| 性能测试场景如何确定用户数？ | 根据历史数据或业务需求，基准→负载→压力递进 |
| 发现 Bug 后如何处理？ | 记录→分类→报告→跟踪→验证关闭 |
| 如何保证语句覆盖率达标？ | 分析代码结构，设计覆盖所有分支的测试数据 |
| 团队如何分工协作？ | 按技能特长分配，定期同步进度，文档统一规范 |
| 遇到技术难题如何解决？ | 先独立排查，再团队讨论，最后寻求技术支持 |
| 测试过程中最大的挑战？ | 结合实际情况，说明应对策略与收获 |

### 心理建设

**赛前：**
- 保证充足睡眠，避免临时突击
- 提前熟悉赛场环境与设备
- 准备备用方案（U 盘备份、离线文档）

**赛中：**
- 严格按时间节点推进，不纠结单题
- 遇到卡壳先跳过，标记后回头处理
- 每完成一个任务做一次深呼吸

**赛后：**
- 不与队友讨论对错，专注复盘
- 记录所有不确定项，赛后统一确认
- 保持平常心，积累经验为下次准备

## 动手实操

1. 组织一次完整 3 小时全真模拟（使用官方样题）
2. 赛后 30 分钟内完成自评打分
3. 制作复盘报告，列出改进清单
4. 制作 10 分钟展示 PPT
5. 进行模拟答辩，录音后回听改进

## 常见坑
- 模拟赛中途查资料——失去模拟意义
- 复盘只看不写——必须书面记录扣分原因
- PPT 文字过多——评委无法快速获取要点
- 答辩超时——每页严格计时，提前演练 3 次
- 心理紧张导致手抖——赛前深呼吸，降低期望值
- 团队复盘互相指责——聚焦问题本身，不追责
