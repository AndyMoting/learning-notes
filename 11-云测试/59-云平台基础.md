# 59-云平台基础

- 理解云计算三种服务模型的区别与适用场景

- 理解云测试的优势与成本管理基本原则

## 核心概念

### 云计算服务模型

| 模型 | 全称 | 管理责任 | 典型用途 |
|------|------|----------|----------|
| IaaS | Infrastructure as a Provider | 用户管理 OS 及以上 | 自定义测试环境、虚拟机集群 |
| PaaS | Platform as a Service | 用户管理应用与数据 | 部署测试应用、数据库服务 |
| SaaS | Software as a Service | 仅使用软件 | 测试管理工具（Jira、TestRail） |

**类比**：IaaS 如同租用毛坯房，自行装修；PaaS 如同租用精装房，拎包入住；SaaS 如同住酒店，直接使用服务。

### AWS 核心服务（测试视角）

| 服务 | 用途 | 测试场景 |
|------|------|----------|
| EC2 | 弹性计算虚拟机 | 搭建测试执行节点、负载生成器 |
| S3 | 对象存储 | 存储测试日志、截图、报告 |
| Lambda | 无服务器函数 | 自动化测试触发器、轻量级验证 |
| CloudWatch | 监控与告警 | 测试环境健康检查、性能指标收集 |
| RDS | 关系型数据库 | 测试数据管理、数据库兼容性测试 |

### Azure 核心服务（测试视角）

| 服务 | 用途 | 测试场景 |
|------|------|----------|
| Virtual Machines | 弹性计算虚拟机 | 搭建 Windows/Linux 测试环境 |
| Blob Storage | 对象存储 | 测试产物归档、日志存储 |
| Azure Functions | 无服务器函数 | CI/CD 测试流水线触发器 |
| Azure Monitor | 监控与告警 | 测试环境指标采集、异常告警 |
| Azure SQL | 关系型数据库 | 数据库迁移测试、性能基准测试 |

### 云测试核心优势

1. **弹性伸缩**：按需创建/销毁测试环境，避免资源闲置
2. **成本优化**：按使用量付费，无需硬件采购周期
3. **地理分布**：多区域部署验证全球化应用
4. **快速交付**：分钟级环境搭建，缩短测试准备时间
5. **一致性**：基础设施即代码（IaC），消除环境差异

### 测试环境搭建流程

```
需求分析 → 选择服务模型 → 编写 IaC 模板 → 自动化部署 → 环境验证 → 测试执行 → 环境销毁
```

## 动手实操

### 使用 AWS CLI 创建 EC2 测试实例

```bash
# 配置 AWS CLI
aws configure
# AWS Access Key ID: [YOUR_KEY]
# AWS Secret Access Key: [YOUR_SECRET]
# Default region name: ap-southeast-1
# Default output format: json

# 创建安全组
aws ec2 create-security-group \
  --group-name test-sg \
  --description "Test environment security group"

# 开放 SSH 和 HTTP 端口
aws ec2 authorize-security-group-ingress \
  --group-name test-sg \
  --protocol tcp --port 22 --cidr 0.0.0.0/0

aws ec2 authorize-security-group-ingress \
  --group-name test-sg \
  --protocol tcp --port 80 --cidr 0.0.0.0/0

# 启动 EC2 实例
aws ec2 run-instances \
  --image-id ami-0c55b159cbfafe1f0 \
  --instance-type t3.medium \
  --key-name my-test-key \
  --security-groups test-sg \
  --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=TestEnv},{Key=Project,Value=ShopTest}]'

# 查看实例状态
aws ec2 describe-instances --filters "Name=tag:Name,Values=TestEnv"
```

### 使用 Terraform 管理测试环境（IaC）

```hcl
# main.tf - AWS 测试环境
provider "aws" {
  region = "ap-southeast-1"
}

resource "aws_vpc" "test_vpc" {
  cidr_block = "10.0.0.0/16"
  tags = {
    Name    = "test-vpc"
    Project = "ShopTest"
  }
}

resource "aws_subnet" "test_subnet" {
  vpc_id     = aws_vpc.test_vpc.id
  cidr_block = "10.0.1.0/24"
  tags = {
    Name = "test-subnet"
  }
}

resource "aws_instance" "test_server" {
  ami           = "ami-0c55b159cbfafe1f0"
  instance_type = "t3.medium"
  subnet_id     = aws_subnet.test_subnet.id

  tags = {
    Name    = "test-server"
    Project = "ShopTest"
    Env     = "testing"
  }
}

resource "aws_s3_bucket" "test_artifacts" {
  bucket = "shoptest-artifacts-${random_string.suffix.result}"
  tags = {
    Project = "ShopTest"
    Purpose = "test-logs-and-reports"
  }
}

resource "random_string" "suffix" {
  length  = 8
  special = false
  upper   = false
}
```

```bash
# 初始化并部署
terraform init

terraform destroy -auto-approve
```

### 使用 Azure CLI 创建测试资源组

```bash
# 登录 Azure
az login

# 创建资源组
az group create \
  --name rg-shoptest \
  --location southeastasia

# 创建测试虚拟机
az vm create \
  --resource-group rg-shoptest \
  --name vm-test-01 \
  --image UbuntuLTS \
  --size Standard_B2s \
  --admin-username testadmin \
  --generate-ssh-keys \
  --tags Project=ShopTest Env=testing

# 开放测试端口
az vm open-port \
  --resource-group rg-shoptest \
  --name vm-test-01 \
  --port 8080

# 创建存储账户（测试产物）
az storage account create \
  --name stshoptest${RANDOM} \
  --resource-group rg-shoptest \
  --location southeastasia \
  --sku Standard_LRS \
  --tags Project=ShopTest

# 查看所有测试资源
az resource list --resource-group rg-shoptest --output table
```

## 常见坑

1. **忘记销毁环境**：测试结束后未及时关闭实例，产生意外费用。解决方案：设置自动销毁策略（如 AWS Instance Scheduler）
2. **安全组配置过宽**：开放 0.0.0.0/0 到所有端口，存在安全风险。解决方案：最小权限原则，仅开放必要端口
3. **区域选择不当**：测试区域与生产区域不一致，导致延迟/合规问题。解决方案：测试区域与生产区域保持一致或选择邻近区域
4. **数据残留**：测试数据未清理，可能包含敏感信息。解决方案：测试完成后执行数据清理脚本，销毁存储资源
5. **IaC 状态文件丢失**：本地 Terraform state 文件丢失导致无法管理资源。解决方案：使用远程后端（S3 + DynamoDB）存储状态
