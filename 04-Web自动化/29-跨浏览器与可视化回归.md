## 核心概念

### 跨浏览器测试策略

跨浏览器测试的目标是验证应用在不同浏览器环境下的功能一致性与视觉还原度。

**测试优先级矩阵：**

| 优先级 | 浏览器 | 市场份额 | 测试深度 |
|--------|--------|----------|----------|
| P0 | Chrome (Chromium) | ~65% | 全量功能 + 视觉 |
| P1 | Safari (WebKit) | ~18% | 全量功能 + 视觉 |
| P2 | Firefox (Gecko) | ~3% | 核心功能 + 视觉 |
| P3 | Edge (Chromium) | ~5% | 核心功能 |
| P4 | IE11/旧版 | <1% | 关键路径（如需要） |

**浏览器兼容性矩阵示例：**

| 功能 | Chrome | Firefox | Safari | Edge |
|------|--------|---------|--------|------|
| 登录 | ✓ | ✓ | ✓ | ✓ |
| 支付 | ✓ | ✓ | ✓ | ✓ |
| 文件上传 | ✓ | ✓ | ✓ | ✓ |
| WebSocket | ✓ | ✓ | ✓ | ✓ |
| CSS Grid | ✓ | ✓ | ✓ | ✓ |
| WebRTC | ✓ | ✓ | ✓ | ✓ |
| 通知 API | ✓ | ✓ | ✗ | ✓ |

### 可视化回归测试

可视化回归测试通过对比当前截图与基线截图，检测 UI 意外变更。

**核心流程：**

```
基线截图（Baseline）
       │
       ▼
  测试执行 → 当前截图（Current）
       │
       ▼
  差异对比（Diff）
       │
       ├── 无差异 → PASS
       │
       └── 有差异 → 人工审核 → 更新基线 / 修复 Bug
```

**基线管理策略：**

| 策略 | 说明 |
|------|------|
| 版本控制 | 基线截图纳入 Git，变更可追溯 |
| 环境隔离 | 不同分辨率/浏览器使用独立基线 |
| 自动更新 | 确认 UI 变更后自动更新基线 |
| 分支管理 | 不同功能分支可维护独立基线 |

### 截图对比工具对比

| 工具 | 类型 | 特点 |
|------|------|------|
| Playwright `to_have_screenshot` | 内置 | 集成度高，支持阈值配置 |
| pixelmatch | 库 | 轻量级，像素级对比 |
| Percy | SaaS | 云端管理，CI 集成，人工审核 |
| Applitools | SaaS | AI 驱动，智能差异检测 |
| BackstopJS | 开源 | 独立工具，配置驱动 |

### pixelmatch 像素级对比

```python
from PIL import Image
import pixelmatch
import numpy as np
from pathlib import Path
import json


class VisualDiffTool:
    """像素级视觉差异检测工具"""

    def __init__(self, baseline_dir: str, diff_dir: str, threshold: float = 0.1):
        self.baseline_dir = Path(baseline_dir)
        self.diff_dir = Path(diff_dir)
        self.threshold = threshold
        self.diff_dir.mkdir(parents=True, exist_ok=True)

    def compare(
        self,
        test_name: str,
        current_image: Image.Image,
        browser: str = "chromium",
        viewport: str = "desktop",
    ) -> dict:
        """执行对比并返回结果"""
        baseline_path = self.baseline_dir / browser / viewport / f"{test_name}.png"
        diff_path = self.diff_dir / browser / viewport / f"{test_name}-diff.png"
        diff_path.parent.mkdir(parents=True, exist_ok=True)

        if not baseline_path.exists():
            # 首次运行：保存为基线
            current_image.save(str(baseline_path))
            return {
                "status": "baseline_created",
                "test_name": test_name,
                "baseline_path": str(baseline_path),
            }

        baseline = Image.open(baseline_path).convert("RGBA")
        current = current_image.convert("RGBA")

        # 尺寸校验
        if baseline.size != current.size:
            return {
                "status": "size_mismatch",
                "test_name": test_name,
                "baseline_size": baseline.size,
                "current_size": current.size,
            }

        width, height = baseline.size
        diff = Image.new("RGBA", (width, height))

        # 执行像素对比
        num_diff_pixels = pixelmatch.pixelmatch(
            np.array(baseline),
            np.array(current),
            np.array(diff),
            width,
            height,
            {
                "threshold": self.threshold,
                "includeAA": True,        # 忽略抗锯齿差异
                "alpha": 0.3,             # 差异图像透明度
                "diff_color": [255, 0, 0],         # 差异像素颜色（红）
                "diff_color_alt": [255, 255, 0],   # 抗锯齿差异颜色（黄）
                "diff_mask": False,
            },
        )

        # 保存差异图像
        if num_diff_pixels > 0:
            diff.save(str(diff_path))

        total_pixels = width * height
        diff_ratio = num_diff_pixels / total_pixels

        result = {
            "status": "passed" if diff_ratio < 0.01 else "failed",
            "test_name": test_name,
            "diff_pixels": num_diff_pixels,
            "total_pixels": total_pixels,
            "diff_ratio": round(diff_ratio, 6),
            "diff_percentage": round(diff_ratio * 100, 4),
            "baseline_path": str(baseline_path),
            "diff_path": str(diff_path) if num_diff_pixels > 0 else None,
        }

        return result

    def compare_all(self, results: list[dict]) -> dict:
        """汇总所有对比结果"""
        total = len(results)
        passed = sum(1 for r in results if r["status"] == "passed")
        failed = sum(1 for r in results if r["status"] == "failed")
        baselines_created = sum(1 for r in results if r["status"] == "baseline_created")

        return {
            "total": total,
            "passed": passed,
            "failed": failed,
            "baselines_created": baselines_created,
            "pass_rate": round(passed / total * 100, 2) if total > 0 else 0,
            "results": results,
        }


# 使用示例
def test_visual_with_pixelmatch(page: Page):
    """使用 pixelmatch 进行视觉对比"""
    tool = VisualDiffTool(
        baseline_dir="baselines",
        diff_dir="diffs",
        threshold=0.1,
    )

    page.goto("https://example.com")
    page.wait_for_load_state("networkidle")

    # 截图
    screenshot_bytes = page.screenshot(full_page=True)
    current_image = Image.open(io.BytesIO(screenshot_bytes))

    # 对比
    result = tool.compare("homepage", current_image, browser="chromium")

    if result["status"] == "baseline_created":
        pytest.skip("基线已创建")

    if result["status"] == "size_mismatch":
        pytest.fail(f"尺寸不匹配: {result['baseline_size']} vs {result['current_size']}")

    assert result["status"] == "passed", (
        f"视觉差异过大: {result['diff_percentage']}% "
        f"({result['diff_pixels']} 像素)\n"
        f"差异图像: {result['diff_path']}"
    )
```

## 常见坑

1. **基线截图的环境依赖性**：同一页面在不同分辨率、不同浏览器、不同操作系统下渲染结果不同。基线必须按"浏览器+分辨率"组合分别维护。

2. **动态内容的处理**：页面中的时间戳、随机推荐、广告等动态内容会导致视觉对比失败。测试前应通过 mock 或 CSS 隐藏消除动态元素。

3. **抗锯齿差异**：不同浏览器/操作系统的字体渲染存在抗锯齿差异。使用 `includeAA=True` 参数忽略纯抗锯齿差异。

4. **CI 环境的字体缺失**：Linux CI 服务器缺少 Windows/macOS 字体，导致文本渲染差异。需安装字体包或使用 Docker 镜像统一环境。

5. **基线更新流程缺失**：UI 变更后需有明确的基线更新流程。建议通过 CI 人工审核后自动更新，避免直接跳过视觉测试。

6. **跨浏览器测试的维护成本**：全量功能在所有浏览器上运行会显著增加执行时间。核心功能全浏览器覆盖，边缘功能仅 Chrome 覆盖。

7. **视觉对比的阈值设置**：阈值过严（如 0.001）导致频繁误报，过宽（如 0.1）会漏掉明显差异。建议从 0.01 开始，根据实际误报率调整。

8. **Safari 的 WebKit 限制**：WebKit 对某些 CSS 属性和 JavaScript API 的支持与 Chromium/Gecko 不同。测试前需确认目标功能在 WebKit 的兼容性。
